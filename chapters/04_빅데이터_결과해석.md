# 4과목: 빅데이터 결과해석

## 📋 과목 개요 & 출제 경향

### 이 과목은 뭘 배우는가?

2과목(빅데이터 탐색)과 3과목(빅데이터 모델링)에서 다양한 분석 모형을 만드는 법을 배웠다. 4과목에서는 **"그래서 이 모형이 잘 만들어진 건가?"**, **"결과를 어떻게 해석하고 보여줄 건가?"**를 다룬다.

쉽게 말해:
- 2~3과목 = 요리하는 법
- 4과목 = **요리 맛 평가 + 예쁘게 플레이팅**

### 출제 경향

| 영역 | 비중 | 핵심 키워드 |
|------|------|-------------|
| 분류 모형 평가 (혼동행렬) | ★★★★★ | 정밀도, 재현율, F1 스코어, ROC/AUC |
| 회귀 모형 평가 | ★★★★ | MSE, RMSE, MAE, MAPE, 결정계수 |
| 군집 분석 평가 | ★★★ | 실루엣 계수, WCSS, 엘보 메서드 |
| 과적합/과소적합 | ★★★★ | 편향-분산 트레이드오프, 규제, 조기종료 |
| 교차 검증 | ★★★★ | K-Fold, LOOCV, 홀드아웃 |
| 하이퍼파라미터 튜닝 | ★★★ | 그리드서치, 랜덤서치, 베이지안 최적화 |
| 경사하강법 옵티마이저 | ★★★ | SGD, 모멘텀, Adam |
| 결과 해석 (R 출력) | ★★★ | 회귀 분석표, 로지스틱 회귀, PCA |
| 시각화 | ★★★ | 시간/공간/관계/분포/비교 시각화, 인포그래픽 |
| 검정 (t검정, F검정, ANOVA) | ★★★ | p-value 해석, 귀무가설/대립가설 |

> **핵심 전략**: 2~3과목 내용을 탄탄히 한 뒤 4과목을 공부하면 시너지가 극대화된다. 4과목을 공부하면서 2~3과목 이해도 깊어지는 구조.

## 1장: 분석 모형 평가

모형을 만들었으면, "이게 잘 만들어졌나?" 평가해야 한다. 지도학습(회귀/분류)은 정답이 있으니 정답과 비교하고, 비지도학습(군집)은 정답이 없으니 "얼마나 잘 뭉쳤나"로 평가한다.

### 1.1 분류 모형 평가 - 혼동행렬(Confusion Matrix)

**한 줄 요약**: 모델이 예측한 것과 실제 정답을 2x2 표로 정리한 것.

**왜 필요한가**: 분류 모델이 "맞았다/틀렸다"만으로는 부족하다. 예를 들어 암 진단 모델이라면, "암인데 정상이라고 한 경우"와 "정상인데 암이라고 한 경우"는 심각성이 완전히 다르다. 혼동행렬은 어디서 어떻게 틀렸는지를 상세하게 보여준다.

**핵심 설명**:

병원에 가서 건강검진을 받는다고 생각해보자.

- 실제로 병이 있는데 "병 있다"고 정확히 판정 --> **TP (True Positive)**: 진짜 양성
- 실제로 병이 없는데 "병 없다"고 정확히 판정 --> **TN (True Negative)**: 진짜 음성
- 실제로 병이 없는데 "병 있다"고 잘못 판정 --> **FP (False Positive)**: 거짓 양성 (오진)
- 실제로 병이 있는데 "병 없다"고 잘못 판정 --> **FN (False Negative)**: 거짓 음성 (놓침)

표로 그리면:

```
                    예측값
                Positive    Negative
실  Positive  |   TP     |    FN    |
제             |----------|----------|
값  Negative  |   FP     |    TN    |
```

> 외우는 법: **True/False = 맞았냐 틀렸냐**, **Positive/Negative = 모델이 뭐라고 했냐(예측값)**

📝 보충: **현실 예시로 이해하는 혼동행렬**

**예시 1: 암 진단 모델** (100명 검사, 실제 암 환자 10명, 정상 90명)

```
                      예측값
                  암(Positive)  정상(Negative)
실제  암(Positive)  |   8 (TP)  |   2 (FN)   |  ← 실제 암 10명
값    정상(Negative) |   5 (FP)  |  85 (TN)   |  ← 실제 정상 90명
                      ↑ 예측 암 13명  ↑ 예측 정상 87명
```

- TP=8: 암인데 암이라고 맞힌 경우
- FN=2: 암인데 정상이라고 **놓친** 경우 (가장 위험!)
- FP=5: 정상인데 암이라고 **오진**한 경우
- TN=85: 정상인데 정상이라고 맞힌 경우

**예시 2: 스팸 메일 필터** (200통 검사, 실제 스팸 60통, 정상 140통)

```
                       예측값
                  스팸(Positive) 정상(Negative)
실제  스팸(Positive)  |  50 (TP)  |  10 (FN)  |  ← 실제 스팸 60통
값    정상(Negative)  |   7 (FP)  | 133 (TN)  |  ← 실제 정상 140통
```

- FN=10: 스팸인데 받은편지함에 들어감 (사용자 불편)
- FP=7: 정상 메일인데 스팸함으로 감 (중요 메일 놓침!)

**⚠️ 시험 포인트**:
- 시험에서 **축이 반대로** 나올 수 있다 (예측이 가로, 실제가 세로 또는 그 반대). **위치가 아니라 의미로 외워야 한다!**
- 혼동행렬 관련 문제는 **매 회차 1문제 이상** 거의 확정 출제
- 숫자가 채워진 혼동행렬을 주고 평가지표를 계산하게 하는 문제 빈출

### 1.2 분류 평가 지표 - 정밀도, 재현율, F1 스코어 등

**한 줄 요약**: 혼동행렬의 숫자들을 조합해서 모델 성능을 다양한 각도로 측정하는 공식들.

**왜 필요한가**: 단순히 "정확도 90%"라고 하면 좋아 보이지만, 100명 중 암 환자가 5명인 데이터에서 모두 "정상"이라고 찍어도 정확도 95%다. 이래서 다양한 지표가 필요하다.

**핵심 설명**:

| 지표 | 공식 | 일상 비유 | 의미 |
|------|------|-----------|------|
| **정확도 (Accuracy)** | (TP + TN) / 전체 | 전체 시험 문제 중 맞힌 비율 | 전체적으로 얼마나 맞혔나 |
| **정밀도 (Precision)** | TP / (TP + FP) | "양성이라고 한 것" 중 진짜 양성 비율 | 모델이 "양성"이라고 말한 것 중 실제로 맞는 비율 |
| **재현율 (Recall)** | TP / (TP + FN) | "실제 양성" 중 모델이 찾아낸 비율 | 실제 양성을 얼마나 놓치지 않고 찾았나 |
| **특이도 (Specificity)** | TN / (TN + FP) | "실제 음성" 중 정확히 음성으로 판정한 비율 | 정상인을 정상이라고 얼마나 잘 판별했나 |
| **F1 Score** | 2 * (정밀도 * 재현율) / (정밀도 + 재현율) | 정밀도와 재현율의 **조화평균** | 두 지표의 균형 잡힌 평가 |

**재현율의 다른 이름들** (시험에 아무 이름으로나 나올 수 있다):
- 민감도 (Sensitivity)
- TPR (True Positive Rate)
- 히트레이트 (Hit Rate)

**정밀도와 재현율은 트레이드오프 관계**:
- 정밀도를 높이려면 → 확실한 것만 "양성"이라고 해야 → 놓치는 양성 증가 → 재현율 하락
- 재현율을 높이려면 → 조금이라도 의심되면 "양성"이라고 해야 → 오진 증가 → 정밀도 하락

이 둘을 동시에 보고 싶을 때 **F1 스코어**(조화평균)를 사용한다.

**F-beta 스코어**: 정밀도와 재현율에 다른 비중을 주고 싶을 때 사용. beta > 1이면 재현율에 비중, beta < 1이면 정밀도에 비중.

📝 보충: **FPR (False Positive Rate) = 위양성률**
- 공식: FPR = FP / (FP + TN) = 1 - 특이도
- 실제 음성(Negative) 중에서 잘못 양성으로 판정한 비율
- ROC 커브의 **가로축**에 사용되는 지표

📝 보충: **"언제 뭘 중시하는지" — 정밀도 vs 재현율 현실 시나리오 가이드**

지표를 외우는 것만으로는 부족하다. **실제 상황에서 어떤 지표를 더 중시해야 하는지** 판단할 줄 알아야 한다.

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    정밀도 vs 재현율: 언제 뭘 중시하나?                      │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  ■ 재현율(Recall)을 중시하는 상황 = "놓치면 큰일"                          │
│    → FN(놓침)의 비용이 매우 높을 때                                       │
│                                                                         │
│    예시 1: 암 진단                                                       │
│      암 환자를 "정상"이라고 놓치면(FN) → 치료 시기를 놓쳐 사망              │
│      정상인을 "암"이라고 오진(FP) → 추가 검사 비용만 발생                   │
│      → FN 비용 >>> FP 비용 → 재현율 중시!                                │
│                                                                         │
│    예시 2: 코로나 선별 검사                                               │
│      감염자를 놓치면 → 지역사회 전파                                      │
│      비감염자를 양성 판정 → 자가격리 불편                                  │
│      → 놓치는 게 훨씬 위험 → 재현율 중시!                                 │
│                                                                         │
│    예시 3: 제조업 불량품 검출                                             │
│      불량품을 출하하면(FN) → 리콜, 브랜드 손상                             │
│      양품을 불량으로 판정(FP) → 재검사 비용                               │
│      → 놓치는 게 더 비쌈 → 재현율 중시!                                  │
│                                                                         │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  ■ 정밀도(Precision)를 중시하는 상황 = "잘못 찍으면 큰일"                  │
│    → FP(오진)의 비용이 매우 높을 때                                       │
│                                                                         │
│    예시 1: 스팸 메일 필터                                                │
│      정상 메일을 스팸으로 처리(FP) → 중요 업무 메일 놓침                    │
│      스팸을 놓침(FN) → 사용자가 직접 삭제하면 됨                          │
│      → 오진이 더 치명적 → 정밀도 중시!                                    │
│                                                                         │
│    예시 2: 추천 시스템                                                    │
│      관심 없는 상품을 추천(FP) → 사용자 이탈, 신뢰 하락                   │
│      관심 있는 상품을 놓침(FN) → 기회비용이지만 사용자는 모름               │
│      → 정밀도 중시!                                                      │
│                                                                         │
│    예시 3: 법원의 유죄 판결                                               │
│      무고한 사람을 유죄로(FP) → 인권 침해 (매우 심각)                      │
│      범인을 놓침(FN) → 물론 나쁘지만, 억울한 사람 만드는 게 더 심각         │
│      → 정밀도 중시! (의심스러우면 무죄)                                    │
│                                                                         │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  ■ F1 Score를 중시하는 상황 = "둘 다 중요"                               │
│    → FP와 FN의 비용이 비슷할 때, 또는 어느 쪽도 포기할 수 없을 때           │
│                                                                         │
│    예시: 뉴스 분류, 감성 분석, 일반적인 텍스트 분류                         │
│      긍정 리뷰를 부정으로(FP)도 문제, 부정을 긍정으로(FN)도 문제            │
│      → 둘 다 균형 있게 잡아야 함 → F1 Score 중시!                         │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

📝 보충: **분류 평가지표 선택 가이드 — 의사결정 플로차트**

```
시작: 분류 모델을 평가해야 한다
  │
  ▼
데이터가 균형적인가? (양성:음성 비율이 비슷한가?)
  │
  ├── YES ──→ 정확도(Accuracy)를 1차 지표로 사용 가능
  │            + F1 Score로 보조 확인
  │
  └── NO (불균형 데이터) ──→ 정확도는 믿을 수 없다!
       │                      (모두 다수 클래스로 찍어도 정확도 높음)
       ▼
     놓치면 큰일인가(FN 비용 높음)?  vs  오진이 큰일인가(FP 비용 높음)?
       │                                    │
       ├── FN 비용 높음                      ├── FP 비용 높음
       │   → 재현율(Recall) 중시              │   → 정밀도(Precision) 중시
       │   예: 암 진단, 사기 탐지             │   예: 스팸 필터, 추천 시스템
       │                                    │
       └── 비슷하거나 판단 어려움             │
           → F1 Score (균형 지표) 사용        │
                                             │
  ▼                                          ▼
모델 A와 B를 비교해야 한다면?
  → ROC/AUC를 사용 (임계값에 독립적인 전체 성능 비교)
  → AUC가 높은 모델이 전반적으로 더 우수
```

📝 보충: **숫자로 직접 계산해보기** (위 암 진단 예시: TP=8, FN=2, FP=5, TN=85)

```
정확도(Accuracy) = (TP + TN) / 전체 = (8 + 85) / 100 = 93/100 = 0.93 (93%)
정밀도(Precision) = TP / (TP + FP) = 8 / (8 + 5) = 8/13 ≈ 0.615 (61.5%)
재현율(Recall)    = TP / (TP + FN) = 8 / (8 + 2) = 8/10 = 0.80 (80%)
특이도(Specificity) = TN / (TN + FP) = 85 / (85 + 5) = 85/90 ≈ 0.944 (94.4%)
FPR              = FP / (FP + TN) = 5 / (5 + 85) = 5/90 ≈ 0.056 (5.6%)
                 = 1 - 특이도 = 1 - 0.944 = 0.056 ✓
F1 Score         = 2 * (0.615 * 0.80) / (0.615 + 0.80)
                 = 2 * 0.492 / 1.415 ≈ 0.696 (69.6%)
```

> 주목: 정확도는 93%로 높아 보이지만, 정밀도 61.5%는 낮다. "암이라고 한 13명 중 5명은 오진"이기 때문. **정확도만 보면 함정에 빠진다!**

**⚠️ 시험 포인트**:
- "실제로 양성인 데이터 중에서 양성으로 정확히 판단한 비율" = **재현율(Recall)** = 민감도(Sensitivity) (10회 기출 70번)
- "F1 스코어를 계산할 때 사용하는 두 가지 지표?" = **정밀도와 재현율** (10회 기출 71번)
- 재현율 = 민감도 = TPR = 히트레이트 → 용어를 **전부** 외워야 함
- F1 스코어 = 정밀도와 재현율의 **조화평균** (산술평균 아님!)
- 공식에 숫자 넣어서 직접 계산하는 문제 대비 필수

### 연습문제 (1장 분류 모형 평가)

**Q1.** 다음 혼동행렬에서 재현율(Recall)은?

```
              예측: 양성   예측: 음성
실제: 양성  |    40     |    10     |
실제: 음성  |    20     |   130     |
```

(1) 0.67  (2) 0.80  (3) 0.85  (4) 0.93

<details>
<summary>정답 및 해설</summary>

**정답: (2)**

재현율 = TP / (TP + FN) = 40 / (40 + 10) = 40/50 = 0.80

- (1) 0.67 = TP / (TP + FP) = 40/60 → 이건 **정밀도(Precision)**. 함정!
- (3) 0.85 = (40+130)/200 → 이건 **정확도(Accuracy)**
- (4) 0.93 = 계산 오류 유도
</details>

**Q2.** 위 혼동행렬에서 F1 Score에 가장 가까운 값은?

(1) 0.53  (2) 0.63  (3) 0.73  (4) 0.83

<details>
<summary>정답 및 해설</summary>

**정답: (3)**

정밀도 = 40/(40+20) = 0.667, 재현율 = 40/(40+10) = 0.80
F1 = 2 * (0.667 * 0.80) / (0.667 + 0.80) = 2 * 0.5336 / 1.467 ≈ 0.727 → 약 0.73

- F1 = **조화평균**이므로 산술평균 (0.667+0.80)/2 = 0.733보다 항상 작거나 같다
</details>

**Q3.** ROC 커브에 대한 설명으로 **틀린 것**은?

(1) 가로축은 FPR(1-특이도), 세로축은 TPR(민감도)이다
(2) AUC가 0.5이면 무작위 추측 수준이다
(3) AUC가 1.0에 가까울수록 모델 성능이 나쁘다
(4) 커브가 왼쪽 상단에 가까울수록 좋은 모델이다

<details>
<summary>정답 및 해설</summary>

**정답: (3)**

AUC가 1.0에 가까울수록 성능이 **좋다** (나쁜 게 아님!). AUC=1.0은 완벽한 분류, AUC=0.5는 랜덤 수준. 수학적으로 AUC 범위는 0~1이지만, 실용적으로 0.5 미만 모델은 예측을 뒤집으면 0.5 이상이 되므로 시험에서는 "0.5~1 범위"로 출제되는 경향이 있다.
</details>

**Q4.** (추가) 다음 혼동행렬을 보고 모든 지표를 계산하시오.

어떤 은행에서 대출 사기 탐지 모델을 만들었다. 전체 1,000건의 대출 신청 중 실제 사기 50건, 정상 950건이다.

```
                       예측값
                  사기(Positive) 정상(Negative)
실제  사기(Positive)  |  42 (TP)  |   8 (FN)  |  ← 실제 사기 50건
값    정상(Negative)  |  38 (FP)  | 912 (TN)  |  ← 실제 정상 950건
```

(가) 정확도, (나) 정밀도, (다) 재현율, (라) 특이도, (마) F1 Score를 각각 구하라.
(바) 이 모델에서 정밀도와 재현율 중 어느 것을 더 중시해야 하는지 이유와 함께 답하라.

<details>
<summary>정답 및 해설</summary>

**(가) 정확도** = (TP + TN) / 전체 = (42 + 912) / 1000 = **0.954 (95.4%)**

**(나) 정밀도** = TP / (TP + FP) = 42 / (42 + 38) = 42/80 = **0.525 (52.5%)**
→ "사기라고 예측한 80건 중 실제 사기는 42건뿐"

**(다) 재현율** = TP / (TP + FN) = 42 / (42 + 8) = 42/50 = **0.84 (84%)**
→ "실제 사기 50건 중 42건을 잡아냄, 8건 놓침"

**(라) 특이도** = TN / (TN + FP) = 912 / (912 + 38) = 912/950 = **0.96 (96%)**

**(마) F1 Score** = 2 * (0.525 * 0.84) / (0.525 + 0.84) = 2 * 0.441 / 1.365 = **0.646 (64.6%)**

**(바)** **재현율을 더 중시해야 한다.**
- 사기를 놓치면(FN) → 은행이 수천만 원의 실제 손실을 입음 (치명적)
- 정상을 사기로 판정하면(FP) → 추가 심사를 진행하면 되므로 비용이 상대적으로 적음
- 따라서 FN의 비용 >>> FP의 비용 → **재현율 중시**

> 함정 주의: 정확도가 95.4%로 높아 보이지만, 정밀도는 52.5%에 불과하다. 불균형 데이터(사기 5%, 정상 95%)에서 정확도는 믿을 수 없다!
</details>

### 1.3 ROC 커브와 AUC

**한 줄 요약**: 분류 모델의 성능을 하나의 그래프(ROC)와 숫자(AUC)로 요약하는 방법.

**왜 필요한가**: 정밀도, 재현율 각각을 따로 보면 모델 A와 B 중 뭐가 더 좋은지 판단하기 어렵다. ROC 커브는 임계값을 바꿔가며 모델의 전체 성능을 한 눈에 보여준다.

**핵심 설명**:

ROC 커브를 카페 직원의 "손님 서비스 능력"에 비유하면:
- 가로축 = FPR (1 - 특이도): "단골이 아닌데 단골이라고 착각한 비율" (실수율)
- 세로축 = TPR (민감도): "진짜 단골을 단골이라고 알아본 비율" (적중률)

```
TPR(민감도)
1.0 |      ___________
    |     /
    |    /          <-- 좋은 모델 (AUC ≈ 0.9)
    |   /
0.5 |  /............  <-- 최악의 모델 (AUC = 0.5, 대각선)
    | /
    |/
0.0 +------------------
   0.0   0.5       1.0
         FPR(1-특이도)
```

- **AUC = ROC 커브 아래 면적**
- AUC = 0.5 → 동전 던지기 수준 (최악)
- AUC = 1.0 → 완벽한 모델 (이상적)
- 일반적으로 0.8~0.9 정도면 괜찮은 모델

📝 보충: **AUC 값에 따른 모델 등급**

```
AUC = 0.5          AUC ≈ 0.7          AUC ≈ 0.9          AUC = 1.0
(랜덤 추측)        (보통)              (우수)              (완벽)

TPR                TPR                 TPR                 TPR
1|  /              1|   /              1| __/              1|----.
 | /                |  /                ||  /               |    |
 |/                 | /                 |/ /                |    |
 +---               +---               +---                +---
  FPR                FPR                FPR                 FPR

면적=삼각형        면적=약간 볼록      면적=많이 볼록      면적=전부 채움
  0.5                0.7                0.9                 1.0
```

| AUC 범위 | 판정 |
|----------|------|
| 0.9 ~ 1.0 | 매우 우수 (Excellent) |
| 0.8 ~ 0.9 | 우수 (Good) |
| 0.7 ~ 0.8 | 보통 (Fair) |
| 0.5 ~ 0.7 | 나쁨 (Poor) |

**⚠️ 시험 포인트**:
- ROC 커브의 가로축 = **FPR (= 1 - 특이도)**, 세로축 = **TPR (= 민감도)**
- AUC 범위: **0.5 ~ 1** (0이 아니라 0.5부터!)
- AUC = 0.5는 "찍기"와 동일
- (💡 2025ver 보충) 이익도표(Gain Chart), 향상도곡선(Lift Curve)도 가끔 출제

📝 **보충: 이익도표(Gain Chart) & 향상도곡선(Lift Curve)**

**이익도표**: 모델이 예측한 확률 순으로 고객을 정렬했을 때, 상위 N%만 타겟팅하면 전체 대비 얼마나 많은 실제 양성을 잡을 수 있는지 보여주는 그래프.
- 비유: 1000명 중 실제 구매자 100명. 모델 없이 500명 홍보하면 50명 잡음. 모델로 상위 200명만 골라 홍보하면 80명 잡음 → **이득(Gain)**

**향상도곡선(Lift Curve)**: 모델을 쓸 때 vs 안 쓸 때 대비 몇 배 효과인지 보여줌.
- Lift = 1이면 모델 없는 것과 동일, Lift > 1이면 모델이 효과적
- 상위 구간일수록 Lift가 높고, 하위로 갈수록 1에 수렴

⚠️ **시험 포인트**: 이익도표는 "누적 반응률", 향상도는 "랜덤 대비 배수"로 구분

### 1.4 회귀 모형 평가 지표

**한 줄 요약**: 회귀 모델이 예측한 수치와 실제 수치의 차이(오차)를 다양한 방식으로 측정하는 공식들.

**왜 필요한가**: 분류는 "맞다/틀리다"를 세면 되지만, 회귀는 연속적인 숫자를 예측하므로 "얼마나 벗어났나"를 재야 한다. 마치 과녁에 화살을 쏘고 "중심에서 얼마나 멀었나"를 재는 것과 같다.

**핵심 설명**:

모든 지표의 핵심 아이디어: **잔차(오차) = 실제값 - 예측값**

| 지표 | 수식 | 설명 | 특징 |
|------|------|------|------|
| **SSE** | Σ(실제 - 예측)² | 잔차 제곱합 | 기본 재료 |
| **MSE** | SSE / n | 잔차 제곱합의 평균 | 경사하강법에서 사용 |
| **MAE** | Σ\|실제 - 예측\| / n | 절대 오차의 평균 | 제곱 대신 절대값 |
| **RMSE** | √MSE | MSE에 루트 | 원래 단위로 복원 |
| **MAPE** | Σ(\|실제-예측\|/\|실제\|) * 100 / n | 퍼센테이지 오차 | 비율(%)로 표현 |

왜 제곱을 하는가?
- 오차가 +3과 -3이면 단순 합산하면 0이 됨 (상쇄)
- 제곱하면 둘 다 9가 되어 상쇄 방지
- 또는 절대값을 씌워도 됨 (MAE 방식)

**결정계수 (R²)**:
- 0 ~ 1 사이 값 (일반적으로 0~1이지만, 모델이 단순 평균보다 나쁘면 **음수**도 가능 — 매우 나쁜 모델을 의미)
- 모델이 데이터를 얼마나 잘 설명하는지를 비율로 표현
- R² = 0.98이면 "이 모델이 데이터의 98%를 설명한다"
- R² = SSR / SST (회귀 제곱합 / 총 제곱합) = 1 - SSE/SST (SST = SSR + SSE이므로 동치. 두 공식 모두 시험에 나옴)

**수정된 결정계수 (Adjusted R²)**:
- 독립변수가 많아지면 R²는 자동으로 올라감 (구조적 한계)
- 독립변수 추가의 "실제 기여도"를 반영하도록 보정한 것
- 다중 회귀에서는 수정된 R²를 사용하는 것이 바람직
- 공식: Adjusted R² = 1 - (1-R²) * (n-1)/(n-p-1)  (p=독립변수 수, n=데이터 수)

📝 보충: **숫자로 직접 계산해보기**

5개 데이터에서 실제값=[10, 20, 30, 40, 50], 예측값=[12, 18, 33, 37, 52]

```
잔차(오차) = 실제 - 예측 = [-2, 2, -3, 3, -2]

MSE  = ((-2)² + 2² + (-3)² + 3² + (-2)²) / 5
     = (4 + 4 + 9 + 9 + 4) / 5 = 30/5 = 6.0

RMSE = √MSE = √6.0 ≈ 2.449
  → "평균적으로 약 2.45만큼 벗어남" (원래 단위로 해석 가능)

MAE  = (|-2| + |2| + |-3| + |3| + |-2|) / 5
     = (2 + 2 + 3 + 3 + 2) / 5 = 12/5 = 2.4

MAPE = (|(-2)/10| + |2/20| + |(-3)/30| + |3/40| + |(-2)/50|) * 100 / 5
     = (0.2 + 0.1 + 0.1 + 0.075 + 0.04) * 100 / 5
     = 0.515 * 100 / 5 = 10.3%
  → "평균적으로 약 10.3%만큼 벗어남"

R²   = 1 - SSE/SST
     SSE = 30 (잔차 제곱합)
     SST = Σ(실제 - 평균)² = (10-30)² + (20-30)² + (30-30)² + (40-30)² + (50-30)²
         = 400 + 100 + 0 + 100 + 400 = 1000
     R² = 1 - 30/1000 = 1 - 0.03 = 0.97
  → "모델이 데이터의 97%를 설명한다"
```

**⚠️ 시험 포인트**:
- MAPE는 "퍼센테이지"니까 **100을 곱한다** (10회 기출 69번: "p가 붙으면 percentage, 곱하기 100")
- MSE, MAE, RMSE, MAPE 수식 **전부 외워야** 함
- 결정계수 R² = SSR/SST, 범위 0~1
- 독립변수 많을 때 → **수정된 결정계수** 사용

### 1.5 군집 분석 평가 지표

**한 줄 요약**: 정답이 없는 군집 분석에서 "군집이 잘 나뉘었나"를 평가하는 방법.

**왜 필요한가**: 군집 분석은 비지도학습이라 정답이 없다. 그래서 "같은 그룹은 뭉치고, 다른 그룹은 떨어져야 좋다"는 직관적 기준으로 평가한다. 학교 반 배정에 비유하면, 같은 반 아이들은 친하고(응집도 높음), 다른 반과는 성향이 다르면(분리도 높음) 잘 나눈 것이다.

**핵심 설명**:

**군집 평가의 핵심 원리**:
- **군집 내 응집도** 높아야 함 (같은 군집끼리 가까움)
- **군집 간 분리도** 높아야 함 (다른 군집끼리 멀음)

#### 던 인덱스 (Dunn Index)
- 가장 간단한 지표
- 군집 간 최소 거리 / 군집 내 최대 거리
- 값이 클수록 좋다

#### 실루엣 계수 (Silhouette Coefficient)
- 가장 많이 출제되는 지표
- 개별 데이터 포인트 기준으로:
  - a = 자기가 속한 군집 내 다른 포인트들과의 **평균 거리**
  - b = 가장 가까운 다른 군집의 포인트들과의 **평균 거리**
  - 실루엣 계수 = (b - a) / max(a, b)
- 범위: **-1 ~ 1**
- 1에 가까울수록 → 군집 분리가 잘 됨
- 0에 가까우면 → 군집 경계에 있음
- 음수면 → 잘못된 군집에 배정됨
- 예: a=2, b=5일 때 → (5-2)/max(2,5) = 3/5 = **0.6** → 잘 분류됨

#### WCSS (Within-Cluster Sum of Squares)
- 군집 내 제곱합
- 각 데이터가 자기 군집 중심으로부터 얼마나 가까운지
- 값이 작을수록 → 군집 내부가 촘촘함

#### 엘보 메서드 (Elbow Method)
- K-Means에서 K(군집 개수)를 결정하는 방법
- K를 1, 2, 3, 4... 늘려가며 WCSS를 계산
- 그래프에 찍으면 처음에 급격히 감소하다가 **완만해지는 지점** 발생
- 이 꺾이는 지점(팔꿈치) = 최적의 K

```
WCSS
  |
  |\
  | \
  |  \
  |   \._____._____.___  <-- 여기서부터 완만
  |         ^
  |     최적의 K
  +---+---+---+---+---+--- K
  1   2   3   4   5   6
```

**⚠️ 시험 포인트**:
- 실루엣 계수 범위: **-1 ~ 1** (1에 가까울수록 좋다)
- WCSS로 엘보 메서드 → **K-Means의 K 결정**에 사용
- 엘보 메서드 = "경사가 완만해지는 지점이 최적의 K"
- 군집 평가 핵심: 군집 내 응집도 ↑, 군집 간 분리도 ↑

### 연습문제 (1장 회귀/군집 평가)

**Q1.** 실제값이 [100, 200, 300]이고 예측값이 [110, 190, 280]일 때, MAPE는?

(1) 약 5.6%  (2) 약 7.2%  (3) 약 10.0%  (4) 약 12.2%

<details>
<summary>정답 및 해설</summary>

**정답: (2)**

MAPE = (1/n) × Σ(|실제-예측|/|실제|) × 100
= (1/3) × (|10/100| + |10/200| + |20/300|) × 100
= (1/3) × (0.1 + 0.05 + 0.0667) × 100
= (1/3) × 0.2167 × 100
= **7.22%** → 정답: **(2) 약 7.2%**

함정: MAPE는 **각 데이터별 비율을 먼저 구한 뒤 평균**낸다. 전체 오차를 먼저 합산하면 틀린다.
</details>

**Q2.** 실루엣 계수에 대한 설명으로 **옳은 것**은?

(1) 범위는 0에서 1이다
(2) 값이 음수이면 군집 경계에 있다는 뜻이다
(3) 값이 1에 가까울수록 군집 분리가 잘 된 것이다
(4) K-Means에서만 사용할 수 있다

- (2) 음수 = **잘못된 군집에 배정**됨. 군집 경계는 0에 가까운 값
- (3) 정답. 1에 가까우면 자기 군집에 잘 속하고, 다른 군집과 잘 분리됨
- (4) 실루엣 계수는 K-Means뿐 아니라 어떤 군집 알고리즘에도 사용 가능
</details>

### 2.1 과적합과 과소적합

> **용어 정리**: 과적합 = 과대적합 = 오버피팅(Overfitting) — 모두 같은 말. 이 문서에서는 **"과적합"**으로 통일.

**한 줄 요약**: 모델이 학습 데이터에 너무 맞추면 과적합, 너무 못 맞추면 과소적합.

**왜 필요한가**: 시험 공부에 비유하면, 기출문제만 달달 외워서 같은 문제가 나오면 100점이지만 새 문제는 못 푸는 게 과적합이고, 공부를 대충 해서 기출도 새 문제도 다 못 푸는 게 과소적합이다. 우리의 목표는 "새 문제도 잘 푸는 일반화된 모델"을 만드는 것.

**핵심 설명**:

```
데이터: *  *    *
          *  *
       *      *
         *  *

과소적합(Underfitting)      적절한 모형         과적합(Overfitting)
────────────────          ∼∼∼∼∼∼∼∼          ∼*∼*∼*∼*∼*∼
직선 하나로 대충           부드러운 곡선        모든 점을 따라감
```

| 구분 | 과소적합 (Underfitting) | 과적합 (Overfitting) |
|------|----------------------|----------------------|
| 모델 복잡도 | 너무 단순 | 너무 복잡 |
| 훈련 데이터 성능 | 낮음 | 높음 |
| 검증 데이터 성능 | 낮음 | 낮음 |
| 훈련-검증 갭 | 작음 (둘 다 낮으니까) | 큼 (훈련은 높고 검증은 낮음) |
| 편향 (Bias) | 높음 | 낮음 |
| 분산 (Variance) | 낮음 | 높음 |
| 비유 | 공부 안 한 학생 | 기출만 외운 학생 |

**편향-분산 트레이드오프 (Bias-Variance Tradeoff)**:
- 편향 = 예측값과 실제값의 **체계적 차이** (활 조준이 항상 왼쪽으로 빗나감)
- 분산 = 예측값이 **얼마나 흩어지는지** (활을 쏠 때마다 맞는 곳이 다름)
- 편향을 줄이려고 모델을 복잡하게 → 분산 증가 (과적합 위험)
- 분산을 줄이려고 모델을 단순하게 → 편향 증가 (과소적합 위험)
- **둘 다 적절한 지점**이 최적의 모델

  (이상적 모델)         (과소적합)           (과적합)           (최악)

   .---.               .---.               .---.               .---.
  / ●●◎ \             /     \             /  ●  \             / ●   \

- 편향과 분산은 **트레이드오프** 관계

### 2.2 과적합 방지 방법

**한 줄 요약**: 데이터를 늘리거나, 모델을 단순화하거나, 규제(정규화)를 적용하는 방법.

**왜 필요한가**: 과적합은 실무에서 가장 흔한 문제다. 방지 방법을 알아야 실용적인 모델을 만들 수 있다.

**핵심 설명**:

| 방법 | 설명 | 비유 |
|------|------|------|
| 데이터 양 증가 | 더 많은 데이터로 학습 | 기출문제를 더 많이 풀기 |
| 차원 축소 | 불필요한 변수 제거 | 시험 범위 외 내용 버리기 |
| 규제 (Regularization) | 가중치에 제약 추가 | 답안지에 글자 수 제한 걸기 |
| 드롭아웃 (Dropout) | 학습 시 일부 노드를 랜덤으로 비활성화 | 조별과제에서 랜덤으로 빠지기 |
| 가지치기 (Pruning) | 의사결정나무에서 불필요한 가지 제거 | 불필요한 질문 줄이기 |
| 교차 검증 | K-Fold 등으로 일반화 확인 | 다양한 모의고사로 실력 점검 |
| 조기 종료 (Early Stopping) | 검증 오차 증가 시 학습 중단 | 공부가 역효과 나기 전에 멈추기 |

**규제(정규화) - 리지와 라쏘**:

| 구분 | 리지 (Ridge, L2) | 라쏘 (Lasso, L1) |
|------|-----------------|-----------------|
| 규제항 | 가중치의 **제곱합** | 가중치의 **절대값 합** |
| 거리 기반 | **유클리디안 거리** | **맨해튼 거리** |
| 계수 처리 | 0에 **가깝게** 만듦 | 0으로 **만들어 버림** |
| 변수 선택 | 하지 않음 | **자동으로 수행** (희소한 해 생성) |
| 비유 | 모든 과목 점수를 깎되 0점은 안 줌 | 불필요한 과목은 아예 0점 처리 |

**⚠️ 시험 포인트**:
- 라쏘(Lasso)가 **희소한 해(Sparse Solution)**를 만드는 이유: **L1 규제가 계수를 0으로 유도**하기 때문 (10회 기출 74번)
- 리지는 0에 가깝게만 만들고, **0으로 만들지는 않음**
- 과적합 방지: 규제 강도를 **높여야** 함 (10회 기출 77번: "규제 강도를 낮추는 건 틀림")
- 규제 수식이 주어지고 "리지인지 라쏘인지" 판별하는 문제 출제됨

### 2.3 조기 종료 (Early Stopping)

**한 줄 요약**: 학습 오차는 줄어도 검증 오차가 다시 커지기 시작하면 학습을 멈추는 기법.

**왜 필요한가**: 학습을 오래 한다고 좋은 게 아니다. 어느 순간 학습 데이터에만 특화되어 새 데이터에 대한 성능이 떨어지기 시작한다.

```
오차
  |
  | \  검증 오차
  |  \    /
  |   \  /        <-- 여기서 멈춰야 함 (조기 종료 지점)
  |    \/
  |     \___  학습 오차 (계속 감소)
  |
  +----------------------------> 학습 횟수(에포크)
```

📝 보충: **학습곡선으로 진단하는 3가지 상태**

```
 과소적합(Underfitting)        적절한 모형              과적합(Overfitting)

오차                         오차                      오차
 |                            |                         |
 |==== 훈련 오차(높음)        | \                        |  검증 오차
 |==== 검증 오차(높음)        |  \--- 검증 오차           |      /
 |                            |   \--- 수렴              |     /
 |  둘 다 높고                |    \___ 훈련 오차         |    /
 |  차이 작음(갭 X)           |        적당한 갭          |   /____ 
 +---> 에포크                 +---> 에포크               |  /       훈련 오차
                                                        | /__________
                                                        +---> 에포크
                                                        큰 갭 = 과적합!
```

- **과소적합**: 훈련/검증 오차 모두 높고, 갭이 작음 → 모델이 너무 단순
- **적절한 모형**: 둘 다 낮고, 적당한 갭으로 수렴
- **과적합**: 훈련 오차는 매우 낮은데 검증 오차가 높거나 증가 → 큰 갭

**⚠️ 시험 포인트**:
- 학습 곡선에서 "훈련/검증이 수렴하면 학습을 계속 진행할 수 없다" → **틀린 설명!** 진행은 할 수 있지만 과적합 위험 (10회 기출 63번: 정답 4번)
- 수렴 후 계속 학습하면 → 검증 오차 증가 → 과적합

### 연습문제 (2장 모형 진단/개선)

(1) 편향이 높으면 과소적합 가능성이 크다
(2) 분산이 높으면 과적합 가능성이 크다
(3) 모델 복잡도를 높이면 편향과 분산이 동시에 감소한다
(4) 총 오차 = 편향² + 분산 + 노이즈 로 분해할 수 있다

(2) 모든 회귀 계수를 0에 가깝게만 만든다
(3) 변수 선택 기능이 없다

- (4) 정답. L1 규제가 계수를 0으로 유도하여 희소한 해(Sparse Solution) 생성

## 3장: 교차 검증

### 3.1 데이터 분할과 홀드아웃

**한 줄 요약**: 수집한 데이터를 학습/검증/평가용으로 나누는 가장 기본적인 방법.

**왜 필요한가**: 모든 데이터로 학습하고 같은 데이터로 평가하면 "시험 문제를 미리 본 것"과 같다. 모델이 진짜 잘하는지 확인하려면, 본 적 없는 데이터로 시험 봐야 한다.

**핵심 설명**:

```
전체 데이터
|=========|=======|====|
  학습용     검증용  평가용
  (Train)   (Val)  (Test)
```

**홀드아웃 (Holdout)**: 데이터를 **한 번만** 나눠서 일부를 학습, 나머지를 평가에 사용하는 방법.
- 장점: 간단
- 단점: 어떤 데이터가 학습/평가에 들어가느냐에 따라 결과가 달라짐 (운에 의존)

**⚠️ 시험 포인트**:
- "데이터셋을 일정 비율로 분리해서 검증 데이터로 사용" = **홀드아웃 검증** (10회 기출 72번)

### 3.2 K-Fold 교차 검증

**한 줄 요약**: 데이터를 K개로 나눈 뒤, 돌아가며 각 조각을 검증에 사용하여 K번 학습-평가하는 방법.

**왜 필요한가**: 홀드아웃은 데이터의 일부만 검증에 쓰이니 아깝고, 결과도 불안정하다. K-Fold는 모든 데이터가 학습에도, 검증에도 사용되니 더 안정적이고 일반화가 잘 된다.

📝 보충: **교차 검증을 왜 하는가? — 동기를 확실히 이해하기**

```
문제 상황: 데이터가 1,000개뿐이다.

방법 1: 홀드아웃 (700개 학습, 300개 평가)
  → 한 번만 평가 → "이번에 300개에 쉬운 데이터가 몰렸을 수도 있지 않나?"
  → 운에 따라 성능 평가가 들쑥날쑥 (신뢰 불가)
  → 300개를 평가에만 쓰니 학습 데이터도 부족

방법 2: K-Fold (5-Fold)
  → 5번 다르게 나눠서 평가 → 5개 결과의 평균
  → 운의 영향을 줄여주고, 모든 데이터가 학습+평가에 한 번씩 참여
  → 더 안정적이고 신뢰할 수 있는 성능 추정

핵심 동기 정리:
  1. 데이터를 최대한 활용하고 싶다 (아까우니까)
  2. 평가 결과의 분산(불안정성)을 줄이고 싶다
  3. 모델의 일반화 성능을 더 정확하게 추정하고 싶다
```

**핵심 설명**:

K=5인 경우를 보자:

```
전체 데이터 500개를 5등분 (각 100개)

┌───────────────────────────────────────────────────────┐
│  Fold 1  │  Fold 2  │  Fold 3  │  Fold 4  │  Fold 5  │
│ (100개)  │ (100개)  │ (100개)  │ (100개)  │ (100개)  │
└───────────────────────────────────────────────────────┘

1회차: [■평가■] [==학습==] [==학습==] [==학습==] [==학습==]  → 성능1 = 0.85
2회차: [==학습==] [■평가■] [==학습==] [==학습==] [==학습==]  → 성능2 = 0.82
3회차: [==학습==] [==학습==] [■평가■] [==학습==] [==학습==]  → 성능3 = 0.88
4회차: [==학습==] [==학습==] [==학습==] [■평가■] [==학습==]  → 성능4 = 0.84
5회차: [==학습==] [==학습==] [==학습==] [==학습==] [■평가■]  → 성능5 = 0.86

최종 성능 = (0.85 + 0.82 + 0.88 + 0.84 + 0.86) / 5 = 0.85

핵심 포인트:
- 매 회차 400개(K-1=4 Fold)로 학습, 100개(1 Fold)로 평가
- 모든 500개 데이터가 정확히 1번씩 평가에 사용됨
- 5개 결과를 평균 → 홀드아웃보다 안정적인 성능 추정
```

- K-1개로 학습, 1개로 평가를 K번 반복
- 모든 데이터가 한 번씩 평가에 사용됨
- 결과를 평균 내면 더 안정적

📝 보충: **Stratified K-Fold (계층적 K-Fold)**

불균형 데이터에서 일반 K-Fold를 하면, 특정 Fold에 소수 클래스가 아예 없을 수 있다. Stratified K-Fold는 **각 Fold에서 클래스 비율을 원본과 동일하게 유지**한다.

```
예: 전체 데이터 = 양성 10%, 음성 90%

일반 K-Fold:     Fold 1에 양성 0개일 수 있음 → 학습 불안정
Stratified K-Fold: 각 Fold에서도 양성 10%, 음성 90% 유지 → 안정적
```

### 3.3 LOOCV (Leave-One-Out Cross Validation)

**한 줄 요약**: 데이터 1개만 평가에 두고 나머지 전부로 학습하는 극단적 교차 검증.

**왜 필요한가**: 데이터가 매우 적을 때 (예: 120개), 20개를 검증에 쓰기 아깝다. 1개만 검증에 쓰고 119개로 학습하면 데이터 활용도가 극대화된다.

- N개 데이터 → N번 학습
- 신뢰도 높지만 **연산량이 매우 많음** → 실제로는 잘 사용되지 않음

**⚠️ 시험 포인트**:
- LOOCV = "하나의 데이터를 검증에 사용하고 나머지를 학습에 사용" (10회 기출 67번: 정답 3번)
- 데이터 수가 적을 때 사용

### 3.4 부트스트래핑 (Bootstrapping)

**한 줄 요약**: 원본 데이터에서 **복원 추출**로 새로운 데이터셋을 여러 개 생성하는 방법.

**왜 필요한가**: 데이터가 부족하거나 불균형할 때, 복원 추출로 데이터를 뻥튀기할 수 있다. 배깅(Bagging)의 기반 기술이기도 하다.

- 복원 추출 → 약 36.8%의 데이터는 한 번도 뽑히지 않음
- 이 뽑히지 않은 데이터를 평가용으로 활용 가능 (OOB: Out-of-Bag)

**비교표**:

| 방법 | 학습 데이터 | 평가 데이터 | 반복 횟수 | 특징 |
|------|-----------|-----------|----------|------|
| 홀드아웃 | 일부 | 나머지 | 1회 | 간단하지만 불안정 |
| K-Fold | K-1 조각 | 1 조각 | K회 | 안정적, 가장 많이 사용 |
| LOOCV | N-1개 | 1개 | N회 | 신뢰도 높지만 연산량 큼 |
| 부트스트래핑 | 복원추출 | OOB | 여러 회 | 데이터 부족 시 유용 |

**⚠️ 시험 포인트**:
- 하이퍼파라미터 10개, K-Fold 10 → 학습 횟수 = **10 * 10 = 100회** (10회 기출 68번)
- QDA는 하이퍼파라미터가 극히 적어 → 10개의 하이퍼파라미터로 100번 학습은 부적절 (라쏘 회귀가 적합)

## 4장: 적합도 검정과 통계 검정

### 4.1 적합도 검정

**한 줄 요약**: 내가 수집한 데이터가 특정 분포(주로 정규분포)를 따르는지 확인하는 검정.

**왜 필요한가**: 많은 통계 분석 기법은 "데이터가 정규분포를 따른다"는 가정 하에 작동한다. 이 가정이 깨지면 분석 결과를 신뢰할 수 없다. 요리하기 전에 "재료가 신선한가?"를 확인하는 것과 같다.

**모수 검정의 전제 조건 3가지**:
1. **정규성**: 데이터가 정규분포를 따르는가?
2. **등분산성**: 그룹 간 분산이 동일한가?
3. **독립성**: 데이터가 서로 독립적인가?

회귀 분석의 가정 4가지: **선분정독** (선형성, 분산의 동질성(등분산), 정규성, 독립성)
- 선형성 제외한 나머지 3가지는 잔차(오차)와 관련된 조건

**QQ Plot (Quantile-Quantile Plot)**:
- 데이터의 분위수를 그래프에 찍어 정규성을 시각적으로 판단
- 점들이 **45도 대각선 위에 분포**하면 → 정규분포를 따름

```
관측값
  |       .
  |     .
  |   .        <-- 대각선에 정렬 = 정규분포 OK
  | .
  +-----------> 이론적 분위수
```

### 4.2 Z 검정, t 검정, F 검정, ANOVA

**한 줄 요약**: 모집단/집단 간 평균이나 분산의 차이가 통계적으로 의미 있는지 확인하는 검정들.

**왜 필요한가**: "A 학교 평균이 B 학교보다 5점 높다"라는 결과가 나왔을 때, 이게 우연인지 진짜 차이인지 판단해야 한다. 통계 검정은 "이 차이가 우연으로 일어났을 확률(p-value)"을 계산해준다.

**핵심 설명**:

| 검정 | 용도 | 핵심 |
|------|------|------|
| **Z 검정** | 표본이 모집단에 속하는지 | 표본 크기 클 때 |
| **t 검정** | 1~2개 집단의 평균 비교 | 표본 크기 작을 때도 가능 |
| **F 검정** | 두 집단의 **분산** 동일성 | F = 표본분산1 / 표본분산2 |
| **ANOVA** | **3개 이상** 집단의 평균 비교 | 회귀 모형 유의성 검정에도 사용 |

**t 검정의 3가지 유형**:

| 유형 | 설명 | 예시 |
|------|------|------|
| **단일 표본** | 하나의 집단 평균이 특정 값과 같은지 | A 공장 분량이 100g인지? |
| **독립 표본** | 서로 다른 두 집단의 평균 비교 | A 학교 vs B 학교 성적 |
| **대응 표본** | 같은 집단에 다른 처리 후 비교 | A 학교에서 새 학습법 적용 전후 성적 |

**독립 표본 t검정 - 등분산 여부**:
- 두 집단의 분산이 같다고 가정 → 일반 독립표본 t검정
- 두 집단의 분산이 다르다고 가정 → **웰치(Welch) t검정**
- 판단 흐름: **F검정으로 등분산 확인** → 등분산이면 일반 t검정, 이분산이면 웰치 t검정

**p-value 해석** (정말 중요!):
- p-value = "귀무가설이 맞다고 가정했을 때, 이런 결과가 나올 확률"
- p-value < 0.05 → 귀무가설 **기각** (통계적으로 유의)
- p-value > 0.05 → 귀무가설을 **기각하지 못함(채택)** (통계적으로 유의하지 않음)
  - ⚠️ 관행적으로 '채택'이라 표현하지만, 엄밀히는 '참이라고 증명된 것이 아니라 기각할 근거가 부족하다'는 뜻

쉽게 말해:
- p-value가 작다 = "이건 우연이 아니야, 진짜 차이가 있어!" → 귀무가설 기각
- p-value가 크다 = "이 정도 차이는 우연히도 생길 수 있어" → 귀무가설 기각하지 못함(채택)

📝 보충: **p-value에 대한 흔한 오해 교정**

| 흔한 오해 (틀림!) | 올바른 해석 |
|-------------------|-------------|
| "p-value = 귀무가설이 참일 확률" | p-value = **귀무가설이 참이라고 가정했을 때**, 현재 데이터만큼 극단적인 결과가 나올 확률 |
| "p-value가 크면 귀무가설이 참" | 귀무가설을 **기각하지 못할 뿐**, 참이라고 증명된 것이 아님 |
| "p < 0.05이면 실질적으로 중요한 차이" | 통계적 유의성 ≠ 실질적 중요성. 표본이 크면 아주 작은 차이도 유의해진다 |
| "p-value = 결과를 신뢰할 확률" | p-value는 확률이지만, "내 결과가 맞을 확률"이 아니다 |

> 시험 팁: "귀무가설이 참일 확률"이라는 선지가 나오면 **틀린 것**이다!

📝 보충: **신뢰구간 vs 예측구간**

| 구분 | 신뢰구간 (Confidence Interval) | 예측구간 (Prediction Interval) |
|------|-------------------------------|-------------------------------|
| 대상 | **평균 반응값** | **개별 새 관측값** |
| 범위 | 좁다 | 넓다 |
| 불확실성 | 회귀선(평균)의 불확실성만 반영 | 회귀선 불확실성 + 개별 데이터의 산포 |
| 비유 | "이 나이대 평균 키는 170~175cm" | "이 나이의 **한 사람** 키는 160~185cm" |

> 핵심: 예측구간이 항상 신뢰구간보다 **넓다** (개별 관측의 변동성 추가)

📝 보충: **다중비교 문제 (Multiple Comparison Problem)**

ANOVA에서 "3개 이상 집단 중 적어도 하나가 다르다"고 나오면, "어떤 집단이 다른가?"를 알기 위해 사후검정(Post-hoc test)을 한다. 이때 비교를 여러 번 하면 1종 오류(가짜 양성)가 증가한다.

- 집단 3개 → 비교 3번 (A-B, A-C, B-C)
- 각 비교마다 5% 오류 → 전체 오류율 ≈ 14.3% (1 - 0.95³)

**보정 방법**:
| 방법 | 설명 |
|------|------|
| **본페로니 보정 (Bonferroni)** | 유의수준을 비교 횟수로 나눔. α/k (예: 0.05/3 ≈ 0.017) |
| **투키(Tukey) HSD** | 모든 쌍별 비교에 특화된 방법 |
| **셰페(Scheffe)** | 가장 보수적, 비교 수가 많을 때 적합 |

> 시험 포인트: 본페로니 보정 = "유의수준을 비교 횟수로 나눈다" → 더 엄격한 기준

**R 출력 해석 예시 (독립표본 t검정)**:

두 학교 A, B의 수학 점수를 95% 신뢰도로 검정:
- 대립가설: "두 학교 평균 차이 ≠ 0" (= 다르다)
- 귀무가설: "두 학교 평균 차이 = 0" (= 같다)
- 양측 검정 (같지 않다 → 크다/작다 모두 포함)
- p-value = 0.51 → 0.05보다 큼 → **귀무가설 기각하지 못함(채택)** → "평균 차이는 통계적으로 유의하지 않다"

**⚠️ 시험 포인트**:
- ANOVA: **3개 이상** 집단의 평균 비교 + 회귀 모형 유의성 검정
- F 검정: 두 집단 **분산의 동일성** 검정 (F = 분산1/분산2)
- p-value < 0.05 → 기각 (유의), p-value > 0.05 → 기각하지 못함(채택) (유의하지 않음)
- 10회 기출 76번: 로지스틱 회귀 결과에서 p-value가 4.34 * 10^(-10) = 매우 작음 → **유의한 관계가 있다** (2번 "유의한 관계 없다"가 틀린 보기)

📝 보충: **ANOVA 분산분석표 실제 구조 + 각 셀의 의미**

예시: 3개 집단(A, B, C), 총 데이터 30개, SSR=120, SSE=80

```
┌──────────┬───────┬──────┬────────┬────────┬──────────┐
│ 요인     │  SS   │  df  │   MS   │   F    │ p-value  │
├──────────┼───────┼──────┼────────┼────────┼──────────┤
│ 회귀(SSR)│  120  │  2   │  60.0  │  20.25 │ < 0.001  │
│ 잔차(SSE)│   80  │  27  │  2.963 │        │          │
│ 전체(SST)│  200  │  29  │        │        │          │
└──────────┴───────┴──────┴────────┴────────┴──────────┘

각 셀의 의미:
- SS(Sum of Squares): 제곱합. SST = SSR + SSE → 200 = 120 + 80
- df(자유도): 회귀=집단수-1=2, 잔차=n-집단수=30-3=27, 전체=n-1=29
- MS(Mean Square): SS를 df로 나눈 것. MSR=120/2=60, MSE=80/27=2.963
- F: MSR / MSE = 60 / 2.963 = 20.25
- p-value < 0.001: 매우 작으므로 → 집단 간 평균 차이가 유의함
```

### 연습문제 (4장 통계 검정)

**Q1.** p-value에 대한 설명으로 **올바른 것**은?

(1) p-value는 귀무가설이 참일 확률이다
(2) p-value가 0.03이면 귀무가설이 참일 확률은 3%이다
(3) p-value가 0.03이면 유의수준 0.05에서 귀무가설을 기각한다
(4) p-value가 클수록 대립가설을 지지하는 증거가 강하다

<details>
<summary>정답 및 해설</summary>

**정답: (3)**

- (1), (2) p-value는 "귀무가설이 참일 확률"이 **아니다**. "귀무가설이 참이라고 가정했을 때 이런 극단적 결과가 나올 확률"이다. 흔한 오해!
- (3) 정답. 0.03 < 0.05이므로 귀무가설을 기각
- (4) p-value가 **작을수록** 대립가설을 지지하는 증거가 강하다
</details>

**Q2.** 분산분석표에서 SST=500, SSR=350, 회귀 자유도=3, 잔차 자유도=16일 때, F 통계량은?

(1) 약 1.87  (2) 약 2.67  (3) 약 12.44  (4) 약 37.33

<details>
<summary>정답 및 해설</summary>

**정답: (3)**

SSE = SST - SSR = 500 - 350 = 150
MSR = SSR / df_회귀 = 350 / 3 ≈ 116.67
MSE = SSE / df_잔차 = 150 / 16 = 9.375
F = MSR / MSE = 116.67 / 9.375 ≈ **12.44**

총 데이터 수 = 자유도 + 1 = (3+16) + 1 = 20개
</details>

### 4.3 비모수 검정

**한 줄 요약**: 모집단의 분포를 모를 때(정규분포 가정 불가) 사용하는 검정 방법.

**왜 필요한가**: t검정, F검정, ANOVA는 모두 "데이터가 정규분포를 따른다"는 가정이 필요한 **모수 검정**이다. 하지만 현실 데이터는 정규분포를 따르지 않는 경우가 많다. 이때 **비모수 검정**을 사용한다.

**핵심 차이**:

| 구분 | 모수 검정 | 비모수 검정 |
|------|----------|------------|
| 분포 가정 | 정규분포 가정 필요 | 분포 가정 불필요 |
| 검정 기준 | **평균** | **순위, 중앙값, 빈도** |
| 예시 | t검정, F검정, ANOVA | 만-휘트니, 윌콕슨, 크루스칼-왈리스 |
| 장점 | 검정력이 높음 | 가정 위반 시에도 사용 가능 |
| 단점 | 가정 위반 시 결과 신뢰 불가 | 모수 검정보다 검정력 낮음 |

**주요 비모수 검정 종류**:

| 검정 방법 | 대응하는 모수 검정 | 용도 |
|----------|------------------|------|
| **만-휘트니 U 검정** (Mann-Whitney) | 독립표본 t검정 | 두 독립 집단의 중앙값 비교 |
| **윌콕슨 부호순위 검정** (Wilcoxon) | 대응표본 t검정 | 짝지어진 두 집단 비교 |
| **크루스칼-왈리스 검정** (Kruskal-Wallis) | 일원분산분석(ANOVA) | 3개 이상 집단 비교 |
| **부호 검정** (Sign Test) | 단일표본 t검정 | 중앙값과 특정 값 비교 |

> 외우는 법: "**만윌크부**" -- 만-휘트니, 윌콕슨, 크루스칼-왈리스, 부호 검정

📝 보충: **순위 검정이란? — 비전공자를 위한 직관적 설명**

비모수 검정이 "순위로 검정한다"는 말이 와닿지 않을 수 있다. 예시로 이해하자.

```
상황: A약과 B약의 효과를 비교하고 싶다.
      데이터가 정규분포를 따르지 않아서 t검정 대신 만-휘트니 검정을 쓴다.

원본 데이터:            순위로 변환:
A약: 12, 45, 8          전체를 섞어서 작은 순으로 순위 매김
B약: 30, 50, 22         
                        값:   8  12  22  30  45  50
                        순위: 1   2   3   4   5   6
                        소속: A   A   B   B   A   B

A약 순위합 = 1 + 2 + 5 = 8
B약 순위합 = 3 + 4 + 6 = 13

→ 순위합의 차이가 통계적으로 유의한지 검정
→ 원래 값의 크기가 아니라 "순서(순위)"만 사용하므로
   극단적 이상치에 덜 민감하고, 분포 가정이 불필요!
```

> 핵심: 비모수 검정은 원래 값을 **순위(등수)**로 바꿔서 비교한다. 그래서 이상치에 강하고, 분포를 몰라도 된다.

**⚠️ 시험 포인트** (11회 출제):
- 만-휘트니 검정은 **순위**로 검정한다. "평균으로 검정한다"는 **틀림**
- "모집단의 분포를 모를 때 사용하는 검정은?" → 비모수 검정
- 비모수 검정은 평균이 아닌 **순위, 중앙값, 빈도**를 사용한다는 것이 핵심

## 5장: 매개변수와 하이퍼파라미터

### 5.1 파라미터 vs 하이퍼파라미터

**한 줄 요약**: 파라미터는 모델이 자동으로 학습하는 값, 하이퍼파라미터는 사람이 직접 설정하는 값.

**왜 필요한가**: 모델을 잘 만들려면 두 가지를 모두 이해해야 한다. 파라미터는 모델이 알아서 찾지만, 하이퍼파라미터는 우리가 잘 골라줘야 모델이 잘 작동한다. 카레를 만들 때 물의 양을 맞추는 건 레시피(파라미터)가 알려주지만, "몇 인분 만들 건지"는 내가 정해야 한다(하이퍼파라미터).

| 구분 | 파라미터 (Parameter) | 하이퍼파라미터 (Hyperparameter) |
|------|---------------------|-------------------------------|
| 결정 주체 | 모델이 **자동 학습** | 사용자가 **수동 설정** |
| 결정 시점 | 학습 **중** 자동 갱신 | 학습 **전** 사전 설정 |
| 목적 | 최적의 모델 구현 | 학습 과정 제어 |
| 예시 | 회귀 계수(w, b), 가중치 | 학습률(α), K-Means의 K, 은닉층 수, 배치 사이즈 |

### 5.2 경사하강법과 학습률

**한 줄 요약**: 손실 함수의 기울기(경사)를 따라 내려가면서 최적의 파라미터를 찾는 알고리즘.

**핵심 설명**:

산에서 가장 낮은 곳(골짜기)을 찾고 싶은데 눈을 감고 있다고 상상하자. 발밑의 경사를 느끼고, 가장 가파르게 내려가는 방향으로 한 발짝씩 내려간다. 이게 경사하강법이다.

수식: **W_new = W_old - α * ∂Loss/∂W**

- W = 가중치 (파라미터) → 학습으로 갱신
- α = 학습률 (하이퍼파라미터) → 사용자가 설정
- ∂Loss/∂W = 손실함수의 기울기(미분) → 내려갈 방향과 강도

**학습률(α)이 중요한 이유**:

| α가 너무 크면 | α가 너무 작으면 | α가 적절하면 |
|---------------|----------------|-------------|
| 경사를 뛰어넘어 **발산** | 찔끔찔끔 내려가 **수렴 느림** | 적절히 내려가 **잘 수렴** |
| 등산을 해버림 | 학습 시간 너무 오래 | 최적 도달 |

### 5.3 배치, 이터레이션, 에포크

**한 줄 요약**: 데이터를 조각내서 경사하강법을 반복하는 단위들.

전체 1,000개 데이터를 100개씩 나눈다면:

```
전체 데이터 1,000개
|--100--|--100--|--100--|--100--|--100--|--100--|--100--|--100--|--100--|--100--|
  배치1   배치2   배치3   ...                                        배치10

배치 사이즈 (Batch Size) = 100
이터레이션 (Iteration) = 10 (1,000 / 100)
에포크 (Epoch) = 1 (전체 데이터를 1번 학습)
```

- **배치 사이즈**: 한 번에 학습하는 데이터 수
- **이터레이션**: 한 에포크 내에서 경사하강법을 수행하는 횟수
- **에포크**: 전체 데이터셋을 한 번 학습하는 단위
- 관계: 배치 사이즈 ↓ → 이터레이션 ↑

### 5.4 하이퍼파라미터 튜닝 방법

**한 줄 요약**: 최적의 하이퍼파라미터 조합을 찾는 4가지 방법.

| 방법 | 설명 | 비유 | 특징 |
|------|------|------|------|
| **매뉴얼 서치** | 경험/감으로 설정 | 노련한 요리사의 감 | 빠르지만 최적 보장 X |
| **그리드 서치** | 모든 조합을 격자형으로 탐색 | 바둑판 칸칸이 다 확인 | 체계적이지만 시간 오래 |
| **랜덤 서치** | 무작위로 조합 탐색 | 복권 뽑기 | 빠르고 효율적 |
| **베이지안 최적화** | 과거 결과 기반 모델링으로 최적 탐색 | 경험에서 배워 전략적 탐색 | 수학적으로 가장 효율 |

**⚠️ 시험 포인트**:
- 그리드 서치 = "가능한 모든 하이퍼파라미터 조합을 **체계적으로** 탐색" (10회 기출 62번: 정답 2번)
- 머신러닝 모델이 수렴하지 않을 때 → "**학습률과 모멘텀을 적절히 조정**" (10회 기출 80번: 정답 2번)
- 확률적 경사하강법(SGD) → **작은 배치** 단위로 학습, 온라인 학습에도 적합, 지역 최소값에 빠질 위험 있음 (10회 기출 65번)

## 6장: 경사하강법 옵티마이저

### 6.1 지역 극소값 문제

**한 줄 요약**: 복잡한 모델의 손실 함수에는 여러 개의 골짜기가 있어서, 가장 깊은 골짜기를 못 찾을 수 있다.

**핵심 설명**:

```
손실
  |
  |    /\      /\
  |   /  \    /  \
  |  /    \  /    \
  | /   극소\/ 극소 \
  |/    값       값   \____  <-- 전역 최소값 (진짜 목표)
  +------------------------------------
           가중치
```

- **전역 최소값 (Global Minimum)**: 진짜로 손실이 가장 작은 지점 (우리의 목표)
- **지역 극소값 (Local Minimum)**: 주변보다는 낮지만 전역 최소는 아닌 지점 (함정)
- 기본 경사하강법은 지역 극소값에 갇힐 수 있음 → 옵티마이저 필요

### 6.2 옵티마이저 종류

| 옵티마이저 | 핵심 아이디어 | 비유 |
|-----------|-------------|------|
| **GD (Gradient Descent)** | 모든 데이터로 기울기 계산 | 모든 길을 조사하고 한 발짝 |
| **SGD (Stochastic GD)** | 랜덤 1개(or 소수) 데이터로 빠르게 | 눈감고 느낌대로 빨리 뛰기 |
| **모멘텀 (Momentum)** | 관성을 줘서 지역 극소값 뛰어넘기 | 자전거로 언덕 넘기 (속도 유지) |
| **AdaGrad** | 가본 곳은 보폭 줄이고, 안 가본 곳은 넓게 | 익숙한 길은 빨리, 새 길은 천천히 |
| **RMSProp** | 맥락 보면서 보폭 조절 | 지형 파악하며 속도 조절 |
| **Adam** | 모멘텀 + RMSProp 결합 | **가장 많이 사용**, 만능 |
| **AdaDelta** | RMSProp의 종종걸음 방지 | 너무 느려지는 거 방지 |

(💡 2025ver 보충) NAG(Nesterov Accelerated Gradient), Nadam도 있으나 아직 세세하게 출제된 적은 없다. 큰 그림만 잡아두면 충분.

📝 보충: **옵티마이저 발전 과정 — 스토리로 이해하기**

옵티마이저를 개별적으로 외우면 헷갈린다. **"왜 다음 것이 나왔는가?"**를 스토리로 연결하면 자연스럽게 기억된다.

```
═══════════════════════════════════════════════════════════════════════
        옵티마이저 발전사: 산을 내려가는 여행자의 진화
═══════════════════════════════════════════════════════════════════════

[1단계] GD (Gradient Descent) — 신중한 여행자
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  방식: 전체 데이터를 다 보고 한 발짝 내려감
  장점: 방향이 정확함
  문제: 데이터가 100만 개면? → 한 발짝 떼는 데 100만 개를 다 봐야 함
        → 너무 느리다!

  "모든 길을 다 조사하는 건 좋은데... 해가 지겠다."

         ↓ 해결: 전부 안 보고 일부만 보자

[2단계] SGD (Stochastic Gradient Descent) — 성급한 여행자
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  방식: 데이터 1개(또는 소수)만 보고 바로 한 발짝
  장점: 매우 빠름, 실시간(온라인) 학습 가능
  문제 1: 방향이 부정확 → 지그재그로 흔들리며 내려감
  문제 2: 지역 극소값(작은 골짜기)에 빠지면 못 나옴

  "빨리 가긴 하는데... 왔다 갔다 지그재그로 비효율적이다."

         ↓ 해결: 관성(속도)을 줘서 직진 성분을 강화하자

[3단계] 모멘텀 (Momentum) — 자전거 탄 여행자
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  방식: 이전 이동 방향의 관성을 유지 (v = 0.9*v_이전 + 기울기)
  장점: 지그재그 감소, 지역 극소값을 관성으로 뛰어넘을 수 있음
  문제: 학습률(보폭)이 모든 파라미터에 동일
        → 자주 업데이트되는 파라미터와 드물게 업데이트되는 파라미터에
           같은 보폭을 쓰는 게 비효율적

  "자전거로 관성 타고 잘 내려가는데... 모든 방향에 같은 속도라니?"

         ↓ 해결: 방향마다 다른 보폭을 쓰자 (적응적 학습률)

[4단계] AdaGrad (Adaptive Gradient) — 학습하는 여행자
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  방식: 많이 업데이트된 파라미터는 보폭 줄이고, 적게 업데이트된 것은 넓게
  장점: 파라미터별 적응적 학습률, 희소 데이터에 강함
  문제: 학습이 진행될수록 보폭이 점점 줄어들어 결국 거의 안 움직임
        (분모에 기울기 제곱이 누적되므로)

  "방향별로 보폭을 다르게 하니 좋은데... 갈수록 발이 안 떨어진다."

         ↓ 해결: 최근 기울기만 반영해서 보폭이 0이 되는 걸 방지

[5단계] RMSProp — 기억력 좋은 여행자
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  방식: 최근 기울기의 이동평균으로 보폭 조절 (오래된 건 잊음)
  장점: AdaGrad의 보폭 소멸 문제 해결
  문제: 관성(모멘텀)이 없음 → 여전히 지역 극소값 탈출이 약함

  "보폭 문제는 해결했는데... 모멘텀이 그립다."

         ↓ 해결: 모멘텀 + 적응적 학습률을 합치자!

[6단계] Adam (Adaptive Moment Estimation) — 최종 보스
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  방식: 모멘텀(1차 모멘트) + RMSProp(2차 모멘트) 결합
  장점: 빠르고, 적응적이고, 지역 극소값도 잘 넘음
  현재: 실무에서 가장 많이 사용되는 기본 옵티마이저

  "관성도 있고, 방향별 보폭 조절도 되고, 거의 만능!"

═══════════════════════════════════════════════════════════════════════
  참고: AdaDelta는 RMSProp과 유사한 시기에 등장한 변형.
  AdaGrad의 보폭 소멸 문제를 학습률 없이 해결하려 시도.
  RMSProp과 접근법이 비슷하지만, 학습률 자체를 자동 결정하는 점이 다름.

  요약 흐름:
  GD(느림) → SGD(빠르지만 불안정) → 모멘텀(관성 추가)
  → AdaGrad(적응적 보폭) → RMSProp/AdaDelta(보폭 소멸 방지)
  → Adam(모멘텀 + 적응적 보폭 = 최강)

  암기: "SMA(rt)" = SGD → Momentum → Adam
═══════════════════════════════════════════════════════════════════════
```

## 7장: 결과 해석

### 7.1 박스 플롯 해석

**한 줄 요약**: 데이터의 분포(중앙값, 사분위수, 이상치)를 한 눈에 보여주는 상자 그래프.

**핵심 설명**:

```
        이상치 *

   ┌──── Q3 (75%)
   │
   │─── 중앙값 (50%)
   │
   └──── Q1 (25%)

   수염 = Q1 - 1.5*IQR ~ Q3 + 1.5*IQR
   IQR = Q3 - Q1
```

해석 포인트:
- A와 B를 비교할 때: 상자가 넓으면 **분산이 크다**
- 중앙값 위치로 **중심 경향** 비교
- 수염 밖의 점 = **이상치 존재**
- 박스 플롯으로는 **평균, 데이터 개수, 개별 데이터값을 알 수 없다** (낚시 문제!)

### 7.2 기술통계량 해석

- 중앙값 < 평균 → 오른쪽으로 꼬리가 긴 분포 → **왜도(Skewness) > 0** (양의 왜도)
- 중앙값 > 평균 → 왼쪽으로 꼬리가 긴 분포 → 왜도 < 0
- NA 개수 → 결측치 수
- 범주형 변수에서 클래스 불균형 → 다운샘플링 또는 오버샘플링 고려

### 7.3 상관관계 히트맵 해석

- 파란색(음수) → **음의 상관관계** (하나 오르면 다른 하나 내림)
- 빨간색(양수) → **양의 상관관계** (함께 오르내림)
- 상관관계가 매우 높은 변수들 → **다중공선성** 의심
- 해결: PCA로 차원 축소하거나 변수를 선택적으로 제거

### 7.4 회귀 분석 결과 해석 (분산분석표 / ANOVA Table)

**한 줄 요약**: 회귀 모형이 통계적으로 유의한지, 각 변수가 의미 있는지를 확인하는 표.

**왜 필요한가**: 회귀 모형을 만들었다고 다 끝이 아니다. "이 모형이 정말 의미 있는 건가?", "이 변수는 정말 영향을 미치나?"를 수치적으로 확인해야 한다.

**회귀 분석 검정 절차**:

```
1단계: 독립변수와 종속변수 설정
   ↓
2단계: 최소제곱법으로 회귀 계수 도출
   ↓
3단계: F 검정으로 모형 전체 유의성 확인  ← ANOVA
   ↓
4단계: t 검정으로 각 회귀 계수 유의성 확인
   ↓
5단계: 결정계수(R²)로 설명력 확인
```

**분산분석표 구조**:

| 요인 | SS | df (자유도) | MS | F |
|------|-----|------------|-----|-----|
| 회귀 (SSR) | | 회귀계수 수 (p) | SSR/p | MSR/MSE |
| 잔차 (SSE) | | n-p-1 | SSE/(n-p-1) | |
| 전체 (SST) | | n-1 | | |

관계: SST = SSR + SSE

**자유도 = n - 1** (왜?):
- 카드 4장을 4명에게 나눌 때, 마지막 사람은 선택권이 없다
- 데이터 n개에서 자유롭게 변할 수 있는 값은 n-1개
- 따라서 총 자유도 = n - 1 → **자유도 + 1 = 데이터 개수**

- 분산분석표에서 빈칸 채우는 문제 자주 출제
- 자유도 + 1 = 데이터 개수 (필수 암기)
- MSR = SSR/자유도, F = MSR/MSE
- R² = SSR/SST로도 계산 가능
- e-09, e-10 같은 표기 = 10의 마이너스 승 = **매우 작은 수** → 유의

### 7.5 로지스틱 회귀 분석 결과 해석

**한 줄 요약**: 분류 문제에 사용하는 회귀 모형으로, 결과가 확률로 나온다.

**10회 기출 76번 해석**:

직업 전환과 자격증 보유 간의 로지스틱 회귀 분석:
- 자격증 보유의 회귀 계수 = 1.5 (**양수**) → 자격증이 직업 전환에 **긍정적 영향**
- p-value = 4.342e-10 → **매우 작음** → **통계적으로 유의한 관계가 있다**
- 잔차 편차가 감소 → 모델 적합도 향상

→ "통계적으로 유의한 관계가 없다"는 **틀린 설명** (정답)

📝 보충: **로지스틱 회귀 - 오즈비(Odds Ratio) 해석**

로지스틱 회귀의 계수는 **로그 오즈(log-odds)**로 해석한다.

```
회귀 계수 β = 1.5일 때:
오즈비(OR) = e^β = e^1.5 ≈ 4.48

의미: 해당 변수가 1 단위 증가하면, "사건 발생 오즈"가 약 4.48배 증가한다.
```

| 회귀 계수 (β) | 오즈비 (e^β) | 해석 |
|---------------|-------------|------|
| β > 0 (양수) | OR > 1 | 변수 증가 → 사건 발생 가능성 **증가** |
| β = 0 | OR = 1 | 변수가 사건 발생에 **영향 없음** |
| β < 0 (음수) | OR < 1 | 변수 증가 → 사건 발생 가능성 **감소** |

> 위 예시에서 자격증 보유의 β=1.5(양수) → OR=4.48 → 자격증이 있으면 직업 전환 오즈가 4.48배 높다 → **긍정적 영향**

📝 보충: **잔차분석 - 회귀 모형의 가정 진단**

회귀 분석의 4가지 가정 **선분정독** 각각을 진단하는 방법:

```
1. 선형성                    2. 등분산성(분산의 동질성)
잔차                         잔차
 |  . .                       |  .  . .
 | . . .  <-- 패턴 없어야 함   |  . . . .  <-- 폭이 일정해야 함
 |. . . .                     | . . . . .
 +---------> 예측값            +---------> 예측값
 패턴 있으면 비선형!          나팔 모양이면 등분산 위반!

3. 정규성                    4. 독립성
관측값                       잔차
 |     .                      |  . . . .
 |   .    <-- QQ Plot에서      | . . . . .  <-- 패턴 없어야 함
 | .        대각선 따라가야 함  |. . . . . .
 +---------> 이론분위수        +---------> 관측 순서
 벗어나면 정규성 위반!        패턴 있으면 자기상관 의심!
                              (더빈-왓슨 검정 사용)
```

| 가정 | 진단 방법 | 위반 시 |
|------|-----------|---------|
| 선형성 | 잔차 vs 예측값 플롯 | 비선형 변환 (로그, 다항식) |
| 등분산성 | 잔차 vs 예측값 플롯 (나팔 형태 확인) | 가중최소제곱법, 로그 변환 |
| 정규성 | QQ Plot, 샤피로-윌크 검정 | 표본 크게, 비모수 검정 |
| 독립성 | 더빈-왓슨(Durbin-Watson) 검정 | 시계열 모형 고려 |

📝 보충: **잔차분석 4가정 위반 시 구체적 대처법 — 상세 가이드**

위 표의 "위반 시" 열만으로는 부족하다. 각 가정이 깨졌을 때 **구체적으로 뭘 해야 하는지** 자세히 정리한다.

```
═══════════════════════════════════════════════════════════════════
         잔차분석 4가정 위반 시 대처법 상세 가이드
═══════════════════════════════════════════════════════════════════

[1] 선형성 위반 — 잔차 vs 예측값 플롯에 곡선 패턴이 보임
───────────────────────────────────────────────────────────────
  증상: 잔차 플롯에서 U자, S자 등 체계적 패턴 발견
  
  대처법:
  ① 변수 변환: 종속변수에 log, sqrt, 역수 변환 적용
     예: y → log(y), y → √y
  ② 다항 회귀: x² 항, x³ 항 추가
     예: y = β0 + β1*x + β2*x² + ε
  ③ 비선형 모형: 선형 회귀 자체를 포기하고 다른 모형 사용
     예: 의사결정나무, 신경망, GAM(일반화 가법 모형)
  ④ 상호작용 항 추가: 변수 간 시너지 효과를 모형에 포함

  시험 빈출: "잔차에 패턴이 보이면?" → 비선형 변환 또는 다항 회귀

[2] 등분산성 위반 (이분산성) — 나팔 모양 또는 부채꼴 패턴
───────────────────────────────────────────────────────────────
  증상: 예측값이 커질수록 잔차의 퍼짐 정도가 달라짐 (나팔 형태)
  
  잔차                   잔차
   |  .                   | .....
   | ...    (나팔형)      |  ...     (부채꼴)
   |......                |   ..
   +------→ 예측값        +------→ 예측값
  
  대처법:
  ① 종속변수 로그 변환: y → log(y) (가장 흔한 방법)
  ② 가중최소제곱법(WLS): 분산이 큰 데이터에는 작은 가중치 부여
  ③ 강건 표준오차(Robust SE): 이분산성에 강건한 표준오차 사용
     (회귀 계수 자체는 바꾸지 않고, 유의성 검정만 보정)
  ④ Box-Cox 변환: 최적의 변환 파라미터를 자동으로 찾아줌

  시험 빈출: "등분산 위반 시 대처?" → 가중최소제곱법(WLS) 또는 로그 변환

[3] 정규성 위반 — QQ Plot에서 점들이 대각선을 크게 벗어남
───────────────────────────────────────────────────────────────
  증상: 잔차의 QQ Plot이 대각선에서 심하게 벗어남
        (꼬리가 두꺼움, 비대칭 등)
  
  대처법:
  ① 표본 크기 늘리기: 중심극한정리에 의해 n ≥ 30이면 덜 민감
  ② 이상치 제거: 극단적 관측값이 정규성을 깨뜨리는 경우
  ③ 변수 변환: log, sqrt 변환으로 분포를 정규에 가깝게
  ④ 비모수 검정: 정규성 가정이 필요 없는 방법 사용
     예: 윌콕슨 순위합 검정 (t검정 대체)
  ⑤ 부트스트랩: 분포 가정 없이 신뢰구간 추정

  시험 빈출: "정규성 위반 시?" → 표본 늘리기, 비모수 검정, 변수 변환

[4] 독립성 위반 (자기상관) — 잔차에 시간적 패턴이 보임
───────────────────────────────────────────────────────────────
  증상: 잔차가 관측 순서에 따라 양/음이 연속적으로 나타남
        더빈-왓슨(DW) 통계량이 2에서 크게 벗어남
        (DW ≈ 0: 양의 자기상관, DW ≈ 4: 음의 자기상관, DW ≈ 2: 독립)
  
  대처법:
  ① 시계열 모형 사용: AR, ARIMA 등 자기상관을 모형화
  ② 시차 변수 추가: 이전 시점의 값을 독립변수로 포함
     예: y_t = β0 + β1*x_t + β2*y_{t-1} + ε
  ③ 차분(Differencing): 시계열의 추세를 제거
  ④ 일반화최소제곱법(GLS): 오차 구조를 명시적으로 모형화

  시험 빈출: "독립성 진단 검정?" → 더빈-왓슨(Durbin-Watson)
             "DW 통계량 ≈ 2이면?" → 자기상관 없음 (독립)

═══════════════════════════════════════════════════════════════════
  핵심 정리:
  선형성 위반 → 변수 변환 / 다항 회귀
  등분산 위반 → WLS / 로그 변환
  정규성 위반 → 표본↑ / 비모수 검정
  독립성 위반 → 시계열 모형 / 더빈-왓슨 검정으로 진단
═══════════════════════════════════════════════════════════════════
```

📝 보충: **AIC/BIC - 모델 선택 기준**

여러 모델 중 어떤 것이 가장 좋은지 비교할 때 사용하는 기준:

| 기준 | 설명 | 특징 |
|------|------|------|
| **AIC (Akaike Information Criterion)** | -2*로그우도 + 2*파라미터 수 | 예측 성능 중시, 덜 보수적 |
| **BIC (Bayesian Information Criterion)** | -2*로그우도 + ln(n)*파라미터 수 | 모델 단순화 중시, 더 보수적 |

- 둘 다 **값이 작을수록 좋은 모델**
- BIC는 데이터 수(n)가 클수록 복잡한 모델에 더 큰 패널티 → 더 단순한 모델 선호
- 두 기준이 다른 모델을 선택하면 → 목적에 따라 판단 (예측 vs 설명)

> 시험 팁: AIC, BIC 모두 **작을수록 좋다**. 헷갈리면 "정보 손실(Information Loss)이 적은 것"으로 기억

### 7.6 교호작용이 포함된 회귀 모형 해석

(💡 2025ver 보충)

**한 줄 요약**: 두 변수가 결합했을 때 시너지(또는 반대) 효과가 있는지를 분석하는 모형.

**핵심 설명**:

임금 = β1 * 나이 + β2 * 직종 + β3 * (나이 * 직종) + 절편

직종이 범주형(Information=1, Industrial=0)일 때:
- Information일 때: β2 * 1 = β2만큼 임금에 추가 영향 → 정보 종사자가 임금 높다
- Industrial일 때: β2 * 0 = 영향 없음 → β2 항이 사라짐

교호작용 항의 p-value = 0.21 > 0.05 → 교호작용은 **유의하지 않음**

📝 보충: **교호작용(Interaction Effect) 쉽게 이해하기**

```
교호작용이 없는 경우:              교호작용이 있는 경우:
(각 변수가 독립적으로 영향)        (두 변수가 결합하여 시너지/상쇄)

매출                               매출
 |     / 광고 多                    |        / 광고 多 (주말에는 효과 폭발)
 |    / 광고 少                     |       /
 |   /                              |      /  
 |  /                               |  ___/ 광고 少 (주말이든 평일이든 비슷)
 | /                                | /
 +---------> 주말/평일              +---------> 주말/평일

두 선이 평행 = 교호작용 없음       두 선이 교차/벌어짐 = 교호작용 있음
```

실생활 예시:
- 운동 + 다이어트: 각각 하면 -3kg, -2kg인데, **동시에** 하면 -8kg → 시너지 교호작용
- 약물 A + 약물 B: 각각은 효과 있는데, **동시에** 복용하면 부작용 → 상쇄 교호작용

## 8장: 주성분 분석(PCA) 결과 해석

### 8.1 주성분 분석의 원리

**한 줄 요약**: 고차원 데이터를 정보 손실을 최소화하면서 저차원으로 줄이는 방법.

**왜 필요한가**: 변수가 100개인 데이터를 그대로 분석하면 복잡하고, 다중공선성 문제도 생긴다. PCA는 가장 중요한 정보를 담은 새로운 축(주성분)을 찾아 차원을 줄여준다.

⚠️ **PCA 전 표준화 필수**: 변수 스케일이 다를 때(예: 키 cm vs 몸무게 kg) 표준화 없이 PCA를 수행하면, 스케일이 큰 변수가 주성분을 지배한다. 시험에서 "표준화 없이 PCA하면?" → 스케일이 큰 변수에 편향된 결과가 나옴.

**핵심 설명**:

교실에서 학생들이 이리저리 흩어져 있다고 생각하자. 사진을 찍는데 한 방향에서만 찍어야 한다. 어느 방향에서 찍으면 학생들이 가장 **넓게 펼쳐져 보일까**? 그 방향이 "첫 번째 주성분"이다.

```
x2
  |        * *
  |      * * *
  |    * * *          PC1 (분산 최대 방향)
  |  * * *          /
  | * * *         /
  |* * *        /
  +--------*-*--------> x1
            \
             PC2 (PC1에 수직)
```

핵심 특성:
1. **첫 번째 주성분 = 분산이 가장 큰 방향** → 정보 손실 최소
2. 각 주성분끼리 **직교(수직)** = 서로 독립 = 겹치는 정보 없음
3. 분산 = 고유값 (선형대수학에서의 표현)
4. **새로운 변수**가 생성됨 (원래 변수의 선형 결합)

### 8.2 PCA 결과 해석

**주성분별 설명력**:

| 주성분 | 표준편차 | 분산(설명력) | 누적 설명력 |
|--------|---------|-------------|-----------|
| PC1 | 가장 높음 | 63% | 63% |
| PC2 | 두 번째 | 17% | 80% |
| PC3 | 세 번째 | 8% | 88% |
| ... | 점점 감소 | ... | ... |
| PC7 | 가장 낮음 | | 100% |

- 원본 = 7차원 (주성분 7개를 써야 100% 설명)
- PC 2개만 사용하면 → 80% 설명력으로 **2차원으로 축소** 가능

### 8.3 스크리 플롯 (Scree Plot)

**한 줄 요약**: 주성분 개수를 몇 개로 할지 결정하는 데 도움을 주는 그래프.

각 주성분의 분산(고유값)을 그래프에 찍으면:

```
분산(고유값)
  |
  |\
  | \
  |  \
  |   \._____._____.___  <-- 여기서부터 수평(완만)
  |         ^
  |    주성분 개수 결정
  +---+---+---+---+---+--- 주성분 번호
  PC1 PC2 PC3 PC4 PC5
```

- **기울기가 완만해지기 직전**의 주성분 개수를 선택
- 엘보 메서드와 유사한 원리
- 연구자 판단에 따라 "수평이 되는 지점"까지 포함할 수도 있음

📝 보충: **누적 분산 설명 비율 그래프** (스크리 플롯과 함께 보는 그래프)

```
분산 설명비율(%)        누적 설명비율(%)
 |                       |
70|█                  100|            ___________
60|█                   90|        ___/
50|█                   80|    ___/ ← 80% 도달 → PC2까지 선택 가능
40|█                   70|   /
30|█ █                 60|  /
20|█ █                 50| /
10|█ █ █ █ █           40|/
  +--+--+--+--+--       +--+--+--+--+--
  PC1 PC2 PC3 PC4 PC5   PC1 PC2 PC3 PC4 PC5

 개별 분산 (막대)        누적 분산 (곡선)
 → 급격히 감소하는 지점   → 80~90% 도달하는 지점
    찾기                     찾기
```

> 주성분 개수 결정 기준: (1) 스크리 플롯에서 꺾이는 지점 (2) 누적 분산 80~90% 지점 (3) 고유값 > 1 기준 (카이저 기준)

**⚠️ 시험 포인트**:
- 주성분 1이 항상 **분산(설명력)이 가장 높다**
- 주성분끼리 **직교 = 독립** (겹치는 정보 없음)
- 스크리 플롯에서 기울기 완만해지는 지점 → 주성분 개수 결정
- 누적 설명력 해석 문제 자주 출제
- 📝 보충: 고유값(Eigenvalue) = 분산, 고유벡터(Eigenvector) = 주성분 방향

### 연습문제 (8장 PCA)

**Q1.** PCA에 대한 설명으로 **틀린 것**은?

(1) 첫 번째 주성분이 가장 큰 분산을 설명한다
(2) 각 주성분은 서로 직교(독립)한다
(3) 원래 변수의 선형 결합으로 새 변수를 만든다
(4) 주성분 개수를 늘리면 차원 축소 효과가 커진다

<details>
<summary>정답 및 해설</summary>

**정답: (4)**

주성분 개수를 늘리면 설명력은 높아지지만 **차원 축소 효과는 줄어든다**. 극단적으로 원본 변수 수만큼 주성분을 쓰면 차원 축소가 전혀 안 된다. PCA의 목적은 **적은 수의 주성분으로 최대한 많은 정보를 보존**하는 것이다.
</details>

**Q2.** 7개 변수에 대해 PCA를 수행했더니 PC1의 분산 설명 비율이 50%, PC2가 20%, PC3가 15%였다. 누적 설명 비율 80%를 달성하려면 최소 몇 개의 주성분이 필요한가?

(1) 1개  (2) 2개  (3) 3개  (4) 4개

<details>
<summary>정답 및 해설</summary>

**정답: (3)**

PC1(50%) + PC2(20%) = 70% → 부족
PC1(50%) + PC2(20%) + PC3(15%) = **85%** → 80% 초과 달성
따라서 최소 **3개**의 주성분이 필요하다.
</details>

## 9장: 시각화

### 9.1 시간 시각화

**한 줄 요약**: 시간의 흐름에 따른 데이터 변화를 보여주는 시각화.

- X축에 시간, Y축에 값
- 대표: 선 그래프(Line Chart), 영역 차트(Area Chart)
- 주식 차트가 대표적 예시

### 9.2 공간 시각화

**한 줄 요약**: 지도 위에 데이터를 표현하는 시각화.

| 유형 | 설명 | 특징 |
|------|------|------|
| **단계 구분도 (Choropleth)** | 색상의 농도로 지역별 값 표현 | **계단형 색상 구간** 사용 |
| **카토그램 (Cartogram)** | 면적을 왜곡하여 값 강조 | **왜곡** 발생 가능 |
| **등치선도** | 등고선처럼 고도/값 표현 | |
| **버블 플롯맵** | 지도 위 버블 크기로 값 표현 | |
| **히트맵** | 같은 면적에 색 농도로 표현 | |

📝 보충: **지오코딩 (Geocoding)** = 주소를 좌표(위도/경도)로 **변환**하는 전처리 기술. '수집'이 아니라 '변환'이 핵심 (시험에서 "공간 데이터 수집 기술"이라고 하면 틀림!)

**⚠️ 시험 포인트**:
- 단계 구분도: **계단형 색상 구간** 사용, 연속형 데이터를 "정확하게" 표현한다는 건 **틀림** (10회 기출 79번: 정답 1번)
- 카토그램: 면적 **왜곡**이 발생 (10회 기출 78번: 정답 4번)
- 지오코딩 ≠ 공간 데이터 수집 기술, 주소 → 좌표 변환

### 9.3 관계 시각화

**한 줄 요약**: 데이터 간의 상관관계, 패턴을 보여주는 시각화.

| 유형 | 변수 수 | 설명 |
|------|---------|------|
| **산점도 (Scatter Plot)** | 2개 | 양의/음의 상관관계 확인 |
| **버블 차트** | 3개 | x축 + y축 + 버블 크기 |
| **히트맵** | 다수 | 상관계수를 색상으로 표현 |
| **덴드로그램** | 다수 | 계층적 군집의 관계 |

**버블 차트 주의점**:
- 면적으로 수량을 비교하므로 **시각적 왜곡** 발생
- 사람 눈은 면적보다 지름에 익숙 → 실제 차이보다 작게 느낌
- 겹치면 이해하기 어려움

**⚠️ 시험 포인트**:
- "변수 간 관계를 시각화하기에 적절하지 않은 것?" → **파이 차트** (비율 표현 용도) (10회 기출 66번: 정답 2번)
- 산점도, 버블 차트, 히트맵은 관계 시각화 가능

### 9.4 분포 시각화

**한 줄 요약**: 데이터의 분포와 비율을 보여주는 시각화.

- 원형 차트 (파이 차트): 비율
- 박스 플롯: 분포, 중앙값, 이상치
- 트리맵: 계층 구조 + 비율

**트리맵 특징**:
- 음수값 표현 어려움
- 이웃한 사각형끼리는 비교 쉬움, 멀리 있는 것끼리는 비교 어려움

> 주의: 같은 차트도 **목적에 따라** 분포, 관계, 비교 시각화로 다르게 분류될 수 있다. 시험에서 무조건 하나로 외우면 안 됨!

### 9.5 비교 시각화

**한 줄 요약**: 그룹 간 차이나 유사성을 비교하는 시각화.

- 막대 차트, 히트맵 등 활용
- 히트맵은 관계 시각화에도, 비교 시각화에도 사용 가능 → **유연하게 생각해야 함**

📝 보충: **주요 시각화 5종 ASCII 예시 + 사용 상황**

**1. 막대 그래프 (Bar Chart)** - 범주별 비교

```
매출(억)
 |
 |  ██
 |  ██  ██
 |  ██  ██  ██
 |  ██  ██  ██  ██
 +--+---+---+---+--
    A   B   C   D   ← 제품별
```
언제: 범주형 데이터의 크기 비교 (팀별 매출, 월별 방문자 수)

**2. 선 그래프 (Line Chart)** - 시간에 따른 변화

```
기온(°C)
30|         *
25|      *     *
20|   *           *
15| *               *
  +--+--+--+--+--+--
   1월 3월 5월 7월 9월 11월
```
언제: 시계열 데이터, 추세 파악 (주가, 기온, 웹 트래픽)

**3. 원형 차트 (Pie Chart)** - 전체 대비 비율

```
      ___
    /  A  \    A: 45%
   | 45%   |   B: 30%
   |  B 30%|   C: 15%
    \ C 15/    D: 10%
     \D10/
      ---
```
언제: 전체 대비 각 항목의 비율 (시장 점유율, 예산 배분)
주의: 항목이 5개 이상이면 가독성 떨어짐 → 막대 그래프가 나음

**4. 산점도 (Scatter Plot)** - 두 변수의 관계

```
y(키)
180| . .     .  .
175|   . . .  .
170|  . . . .
165| .  . .
160|. .
   +--+--+--+--+--
   50 55 60 65 70  x(몸무게)
   → 양의 상관관계 (우상향)
```
언제: 두 연속형 변수의 상관관계 확인 (키-몸무게, 공부시간-성적)

**5. 히트맵 (Heatmap)** - 행렬 데이터의 패턴

```
         수학  영어  과학
  김철수 |████|░░░░|██░░|     ████ = 높은 값 (진한 색)
  이영희 |░░░░|████|██░░|     ██░░ = 중간 값
  박지훈 |██░░|██░░|████|     ░░░░ = 낮은 값
```
언제: 다차원 데이터 패턴 파악 (상관행렬, 요일-시간대별 방문자)

**시각화 선택 가이드**:

| 목적 | 추천 시각화 |
|------|-----------|
| 범주 간 크기 비교 | 막대 그래프 |
| 시간에 따른 변화 | 선 그래프 |
| 전체 대비 비율 | 원형 차트 (항목 적을 때) |
| 두 변수 관계 | 산점도 |
| 다차원 패턴/상관 | 히트맵 |
| 분포 형태 | 히스토그램, 박스플롯 |
| 지리적 분포 | 단계구분도, 카토그램 |

📝 보충: **대시보드 설계 원칙**

| 원칙 | 설명 |
|------|------|
| **한눈에 파악** | 핵심 KPI를 상단에 배치, 스크롤 없이 전체 파악 가능 |
| **일관된 레이아웃** | 같은 유형의 정보는 같은 위치/형식 |
| **적절한 차트 선택** | 데이터 특성에 맞는 시각화 (위 가이드 참고) |
| **색상 절제** | 핵심 데이터만 강조색, 나머지는 중립색 |
| **인터랙티브** | 필터, 드릴다운으로 상세 탐색 지원 |
| **5초 규칙** | 대시보드를 5초 보고 핵심 메시지를 파악할 수 있어야 함 |

📝 보충: **인포그래픽 vs 데이터 시각화 vs 대시보드 비교**

| 구분 | 데이터 시각화 | 인포그래픽 | 대시보드 |
|------|-------------|-----------|---------|
| 목적 | 정보 전달/탐색 | 설득/스토리텔링 | 모니터링/의사결정 |
| 데이터 | 원 데이터 | 가공 데이터 | 실시간/집계 데이터 |
| 상호작용 | 제한적 | 없음 (정적) | 높음 (필터, 드릴다운) |
| 대상 | 분석가 | 일반 대중 | 의사결정자 |

### 연습문제 (9~10장 시각화/인포그래픽)

**Q1.** 다음 중 "변수 간 관계"를 시각화하기에 **가장 부적절한 것**은?

(1) 산점도  (2) 원형 차트  (3) 버블 차트  (4) 히트맵

**Q2.** 인포그래픽에 대한 설명으로 **옳은 것**은?

(1) 데이터 시각화와 동일한 개념이다
(2) 원 데이터를 그대로 사용한다
(3) 정보형 메시지를 전달하는 것이 주 목적이다
(4) 설득형 메시지 전달이 목적이며 가공된 데이터를 사용한다

- (2) 인포그래픽은 **가공된** 데이터를 사용
- (3) 정보형이 아니라 **설득형** 메시지
- (4) 정답. 설득이 목적이고 데이터를 가공하여 시각적으로 표현
</details>

### 9.6 동적 시각화와 대화형 시각화

**한 줄 요약**: 사용자가 클릭, 드래그, 줌 등으로 상호작용할 수 있는 시각화.

**정적 vs 동적 vs 대화형 시각화**:

| 구분 | 정적 시각화 | 동적 시각화 | 대화형(인터랙티브) 시각화 |
|------|-----------|-----------|----------------------|
| 상호작용 | 없음 | 애니메이션/전환 효과 | 사용자 입력에 반응 |
| 데이터 갱신 | 고정 | 시간에 따라 변화 | 실시간 필터링 가능 |
| 예시 | 보고서 차트, 인포그래픽 | 시간별 변화 애니메이션 | 대시보드, 드릴다운 |
| 도구 | matplotlib, Excel | D3.js, Plotly | Tableau, Power BI, Bokeh |

**주요 동적/대화형 시각화 도구**:

| 도구 | 특징 | 분류 |
|------|------|------|
| **D3.js** | JavaScript 기반, 웹 브라우저에서 동작, 자유도 최고 | 동적/대화형 |
| **Plotly** | Python/R/JS 지원, 인터랙티브 차트 라이브러리 | 대화형 |
| **Tableau** | 드래그앤드롭 방식, 비즈니스 대시보드에 특화 | 대화형/대시보드 |
| **Power BI** | Microsoft 생태계, 엑셀 연동 강점 | 대화형/대시보드 |
| **Bokeh** | Python 기반, 웹 기반 인터랙티브 시각화 | 대화형 |

## 10장: 인포그래픽

### 10.1 데이터 시각화 vs 인포그래픽

**한 줄 요약**: 데이터 시각화는 정보 전달, 인포그래픽은 설득이 목적.

| 구분 | 데이터 시각화 | 인포그래픽 |
|------|-------------|-----------|
| 메시지 유형 | **정보형** 메시지 | **설득형** 메시지 |
| 데이터 | 로우 데이터 그대로 | **가공**된 데이터 |
| 원데이터 취급 | O | **X** |
| 예시 | 주식 그래프 | 공익 광고 포스터 |
| 초점 | 정확한 정보 전달 | 시각적 설득력 |

**⚠️ 시험 포인트**:
- 인포그래픽은 "데이터 시각화와 동일한 개념"이라는 건 **틀림** (10회 기출 61번: 정답 3번)
- 인포그래픽 ≠ 데이터 시각화 (목적과 표현 방식이 다름, 별도로 수행)

### 10.2 인포그래픽의 원리

| 원리 | 설명 |
|------|------|
| 단순성 | 복잡하지 않게 |
| 명확성 | 메시지가 분명하게 |
| 중요성 | 핵심만 담기 |
| 일관성 | 스타일 통일 |
| 가독성 | 잘 읽히게 |
| 효과성 | 실제로 효과 있게 |
| 독자 대상 | 특정 타겟 고려 |

**오컴의 면도날 (Occam's Razor)**:
- 면도날 = 불필요한 것을 잘라낸다
- **복잡한 설명보다 단순한 설명이 선호**되어야 한다
- 공익 광고 포스터에 정보를 과하게 넣으면 오히려 효과가 떨어짐

### 연습문제 (10장 인포그래픽)

**Q1.** 인포그래픽에 대한 설명으로 **틀린** 것은?
1. 데이터를 시각적으로 가공하여 정보를 전달한다
2. 오컴의 면도날 원리에 따라 단순할수록 효과적이다
3. 실시간으로 데이터가 갱신되는 대화형 시각화이다
4. 비전문가도 쉽게 이해할 수 있도록 디자인한다

<details>
<summary>정답 및 해설</summary>

**정답: (3)**

실시간 갱신 + 대화형은 **대시보드**의 특징이다. 인포그래픽은 **정적인 시각 자료**로, 한 번 제작하면 고정됨. 이 둘의 차이는 시험 단골 포인트.
</details>

**Q2.** 다음 중 인포그래픽과 데이터 시각화의 차이로 **옳은** 것은?
1. 인포그래픽은 원본 데이터를 그대로 사용한다
2. 데이터 시각화는 스토리텔링이 핵심이다
3. 인포그래픽은 가공된 데이터 + 디자인 + 스토리텔링이 결합된다
4. 데이터 시각화는 비전문가 대상이다

<details>
<summary>정답 및 해설</summary>

**정답: (3)**

데이터 시각화 = 원본 데이터를 차트/그래프로 표현 (전문가 대상), 인포그래픽 = 가공된 데이터 + 디자인 + 스토리텔링 (일반 대중 대상). 1번은 데이터 시각화 설명, 2번은 인포그래픽 설명, 4번은 반대.
</details>

## 11장: 분석 결과 활용 & 비즈니스 기여도 평가

### 11.1 비즈니스 기여도 평가

**한 줄 요약**: 분석 결과가 실제 비즈니스에 얼마나 도움이 됐는지 평가하는 방법.

- 금전적 성과 (매출 증가, 비용 절감)
- 비금전적 성과 (고객 만족도, 프로세스 개선)
- 평가 프로세스에 따라 체계적으로 진행

### 11.2 ROI (투자 대비 수익률)

**한 줄 요약**: 분석 프로젝트에 투자한 비용 대비 얼마나 이익을 얻었는지를 측정하는 지표.

**공식**: ROI = (순이익 / 투자비용) x 100%

**예시**: 빅데이터 분석 프로젝트에 1억 원 투자, 매출 3억 원 증가 → ROI = (3억-1억)/1억 x 100% = **200%**

| ROI 값 | 해석 |
|--------|------|
| > 0% | 투자 대비 이익 발생 |
| = 0% | 본전 |
| < 0% | 손실 |

**⚠️ 시험 포인트**:
- ROI는 **금전적 성과** 평가 지표이다
- ROI만으로 프로젝트 가치를 100% 판단할 수 없음 (비금전적 성과도 고려 필요)
- ROI가 높아도 리스크가 클 수 있음 → 비용 편익 분석(Cost-Benefit Analysis)과 함께 고려

### 11.3 A/B 테스트

**한 줄 요약**: 두 가지 버전(A, B)을 실제 사용자에게 무작위로 보여주고 어느 쪽이 더 효과적인지 비교하는 실험.

**왜 필요한가**: "이 분석 결과를 실제 적용하면 정말 효과가 있을까?"를 실험으로 검증하는 방법. 분석 결과를 비즈니스에 적용하기 전에 A/B 테스트로 실효성을 확인한다.

**구조**:
- **대조군 (A)**: 기존 방식 (변경 없음)
- **실험군 (B)**: 새로운 방식 (분석 결과 적용)
- **무작위 배정**: 사용자를 랜덤으로 A/B 그룹에 배분
- **통계적 검정**: 결과 차이가 유의한지 p-value로 판단

```
A/B 테스트 전체 흐름:

  전체 사용자 1,000명
        │
        ▼
  ┌─────────────┐
  │  무작위 배정  │
  └──┬──────┬───┘
     ▼      ▼
  ┌──────┐ ┌──────┐
  │ A그룹│ │ B그룹│
  │500명 │ │500명 │
  │(기존)│ │(변경)│
  │파란색│ │빨간색│
  │버튼  │ │버튼  │
  └──┬───┘ └──┬───┘
     ▼        ▼
  클릭률     클릭률
   3.2%      4.1%
     │        │
     └───┬────┘
         ▼
  통계 검정 (t검정 등)
  p-value = 0.02 < 0.05
         │
         ▼
  "차이가 유의하다"
  → B안(빨간 버튼) 채택!
```

**예시**: 웹사이트 버튼 색상을 파란색(A) vs 빨간색(B)으로 나눠 클릭률 비교

**⚠️ 시험 포인트**:
- A/B 테스트의 핵심은 **무작위 배정** + **통계적 유의성 검정**
- 표본 크기가 충분해야 신뢰할 수 있는 결과를 얻음
- 한 번에 **하나의 변수**만 변경해야 원인을 특정할 수 있음 (다변량 테스트는 별도)

### 11.4 분석 보고서 작성법

**한 줄 요약**: 분석 결과를 의사결정자가 이해하고 활용할 수 있도록 체계적으로 정리하는 문서.

**보고서 기본 구성**:

| 항목 | 내용 | 핵심 |
|------|------|------|
| 1. 요약 (Executive Summary) | 핵심 발견 사항, 권고 사항 | **가장 먼저** 읽히는 부분 |
| 2. 분석 배경/목적 | 왜 이 분석을 했는지 | 비즈니스 문제 정의 |
| 3. 분석 방법 | 사용한 데이터, 모델, 기법 | 재현 가능하도록 기술 |
| 4. 분석 결과 | 주요 발견 사항, 시각화 포함 | 차트/그래프 활용 |
| 5. 결론 및 제언 | 비즈니스 적용 방안, 한계점 | 실행 가능한 제안 |

**보고서 작성 원칙**:
- **대상에 맞는 수준**: 경영진에게는 핵심 요약, 기술팀에게는 상세 기술
- **시각화 활용**: 텍스트보다 차트가 직관적 → 핵심 결과는 반드시 시각화
- **한계점 명시**: 데이터 한계, 모델 한계를 솔직하게 기술 (신뢰도 향상)
- **실행 가능한 제언**: "매출이 떨어졌다"가 아니라 "20대 타겟 마케팅을 강화하라"

📝 보충: **좋은 보고서 vs 나쁜 보고서 비교**

```
나쁜 보고서 (X):
  "분석 결과 고객 이탈률이 증가 추세입니다.
   다양한 요인이 영향을 미치고 있으며,
   추가 분석이 필요합니다."
  → 그래서 뭘 하라는 건지 모름. 막연함.

좋은 보고서 (O):
  "지난 분기 대비 고객 이탈률 12% 증가 (25% → 37%).
   주요 원인: 가입 후 30일 내 미접속 고객의 이탈률이 68%.
   제언: 가입 7일차에 맞춤형 리텐션 이메일 자동 발송 도입.
   예상 효과: 이탈률 8~10%p 감소 (유사 사례 기반)."
  → 숫자 있고, 원인 있고, 실행 가능한 제안 있음.
```

### 11.5 분석 결과 활용 프로세스

분석 결과를 실제로 적용하기 위한 단계적 접근 방법. 특별히 어려운 내용은 아니므로 교재를 한 번 읽어보면 충분하다.

**⚠️ 시험 포인트**:
- "분석 결과 해석 시 데이터 품질 문제로 가장 적절한 것?" → **"결측값이 많아 신뢰도가 떨어진다"** (10회 기출 75번: 정답 1번)
- 모델 정확도, 시각화, 하이퍼파라미터 튜닝은 데이터 품질 문제가 아님

### 연습문제 (11장 분석 결과 활용)

**Q1.** 분석 결과를 시각화할 때, 대시보드 설계 원칙으로 **적절하지 않은** 것은?
1. 핵심 지표를 한눈에 볼 수 있도록 배치한다
2. 가능한 많은 차트를 하나의 화면에 넣는다
3. 사용자가 필터링/드릴다운할 수 있게 한다
4. 실시간 또는 주기적으로 데이터가 갱신된다

<details>
<summary>정답 및 해설</summary>

**정답: (2)**

대시보드의 핵심은 **"적은 것이 많은 것"**. 너무 많은 차트를 넣으면 오히려 핵심 메시지가 묻힌다. 3~5개의 핵심 KPI에 집중해야 한다.
</details>

**Q2.** 분석 결과의 비즈니스 기여도를 평가할 때, 다음 중 **비금전적 성과**에 해당하는 것은?

(1) 매출 10% 증가  (2) 운영비 20% 절감  (3) 고객 만족도 향상  (4) ROI 150% 달성

<details>
<summary>정답 및 해설</summary>

**정답: (3)**

매출 증가, 운영비 절감, ROI는 모두 금전적 성과이다. 고객 만족도는 수치화할 수 있지만 직접적인 금전적 지표가 아닌 **비금전적 성과**에 해당한다.
</details>

## 최종 체크리스트

### 필수 암기 공식
- [ ] 혼동행렬의 TP, TN, FP, FN 정의
- [ ] 정밀도 = TP / (TP + FP)
- [ ] 재현율 = TP / (TP + FN) = 민감도 = TPR = 히트레이트
- [ ] 특이도 = TN / (TN + FP)
- [ ] FPR = FP / (FP + TN) = 1 - 특이도
- [ ] F1 Score = 2 * 정밀도 * 재현율 / (정밀도 + 재현율)
- [ ] AUC 범위: 0.5 ~ 1
- [ ] MSE, MAE, RMSE, MAPE 수식 전부
- [ ] R² = SSR / SST = 1 - SSE/SST
- [ ] Adjusted R² = 1 - (1-R²)(n-1)/(n-p-1)
- [ ] 실루엣 계수 범위: -1 ~ 1
- [ ] 오즈비 = e^(회귀계수)
- [ ] 본페로니 보정: α/k (비교 횟수로 나눔)

### 암기법 모음
- **혼동행렬 읽기**: "**T**rue/**F**alse = 맞았냐 틀렸냐, **P**ositive/**N**egative = 뭐라고 예측했냐" → TP=양성 맞춤, FP=양성이라 했는데 틀림
- **재현율의 4가지 이름**: "**재민티히**" = 재현율 = 민감도 = TPR = 히트레이트 (다 같은 것!)
- **리지 vs 라쏘**: "**리L2유** 라L1맨" → 리지=L2=유클리디안, 라쏘=L1=맨해튼
- **옵티마이저 순서**: "**SMA**rt" → SGD → Momentum → Adam (발전 순서)
- **잔차분석 4가정**: "**선분정독**" = 선형성, 분산 동질성(등분산), 정규성, 독립성

### 필수 암기 개념
- [ ] 과적합 = 과대적합 = 오버피팅 (같은 말)
- [ ] 편향-분산 트레이드오프 (과녁 비유)
- [ ] 파라미터 vs 하이퍼파라미터 차이
- [ ] K-Fold: K-1개 학습, 1개 평가, K번 반복
- [ ] LOOCV: 1개 평가, N-1개 학습
- [ ] 자유도 + 1 = 데이터 개수
- [ ] p-value < 0.05 → 유의 (귀무가설 기각)
- [ ] p-value ≠ "귀무가설이 참일 확률" (흔한 오해!)
- [ ] 리지(L2) vs 라쏘(L1) 차이
- [ ] 인포그래픽 ≠ 데이터 시각화
- [ ] 오컴의 면도날 = 단순할수록 좋다
- [ ] AIC, BIC = 작을수록 좋다 (모델 선택 기준)
- [ ] 신뢰구간(평균) vs 예측구간(개별) → 예측구간이 항상 넓음
- [ ] 잔차분석 4가지: 선분정독 (선형성, 분산동질성, 정규성, 독립성)
